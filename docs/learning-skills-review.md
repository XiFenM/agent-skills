# 学习类 Skill 合并升级决策与评审记录

本文记录学习类 Skill 在质量评估与合并升级阶段的已确认决策、待研究问题和后续实施边界。
除非另有明确记录，本文中的“目标状态”不表示相关 `SKILL.md`、脚本或消费仓库已经完成修改。

## 当前范围

本轮评审涵盖以下 6 个自创 Skill：

- `english-coach`
- `learn-by-practice`
- `memo-cards`
- `resource-planning`
- `study-companion`
- `study-log`

## 已确认决策（2026-08-10）

### D1：三个下游或上游能力继续保持独立

以下 Skill 不并入主学习流程：

- `english-coach`：继续负责技术学习中的英语反馈，以及学习后的英语专项复盘。
- `memo-cards`：继续负责把成熟的英语或技术学习素材转换为墨墨记忆卡导入数据。
- `resource-planning`：继续负责学习资料周更、候选治理和经用户确认后的课程晋级。

后续仍可分别提高它们的通用性、触发精度和质量，但不改变其独立 Skill 的定位。

### D2：学习对话提取能力统一归 `study-log`

`study-log` 现有的对话提取能力，需要与 `learn-by-practice` 中的学习记录／对话提取能力合并统一。
完成升级后：

- `study-log` 是学习对话发现、选择、清洗、边界截取和提取能力的唯一归属；
- 合并时保留两边已有的有效能力，包括多客户端发现、日期或语义边界选择、可见对话清洗、来源信息、完整性校验和现有测试覆盖；
- `learn-by-practice` 不再自行保存对话提取脚本或对话提取流程；
- `learn-by-practice` 如需学习记录或对话材料，应调用 `study-log` 或消费其产物，而不是维护第二套实现。

以下实现细节尚未决定：

- `study-log` 最终提供一个输出模式，还是分别提供“可追溯原始对话归档”和“结构化过程记录”两个模式；
- 两类输出各自的目录、格式、事实源地位和保留周期；
- `learn-by-practice` 在暂停、课程完成或其他阶段调用 `study-log` 的具体时机；
- 现有脚本、参考文档和测试的迁移边界。

### D3：`study-companion` 与 `learn-by-practice` 合并升级

`study-companion` 与 `learn-by-practice` 不再以两套互相竞争的主学习流程长期并存。
目标是吸收双方有效能力，形成职责统一、状态一致、可支持不同学习场景的新学习流程。

合并方案必须先完成细致的流程差异研究，再由用户共同决定。当前尚未决定：

- 最终保留的 Skill 名称和目录；
- 是一个 Skill 内的多模式，还是通用内核配项目配置／参考资料；
- “先问后讲”与“完整案例讲解”如何组合；
- 微动作带练与正式练习契约如何衔接；
- PlanA 断点、进度、文章与通用 lesson archive 的事实源关系；
- 暂停、收工、主题完成、课程完成和 mastery gate 的统一状态模型；
- PlanA 专用路径、文章模板和学习偏好应放在中央 Skill、消费仓库配置还是参考资料中。

## 当前禁止事项

在上述开放问题得到用户确认前：

- 不修改 6 个学习类 Skill 的内容；
- 不移动或删除 `study-log`、`learn-by-practice` 的脚本、参考资料和测试；
- 不宣布任何旧 Skill 已被弃用；
- 不修改 PlanA 或 programming-lab 的学习状态、进度、断点和文章；
- 不把本文件中的候选设计解读为最终实现授权。

## 下一阶段研究议程

下一步逐阶段对照 `study-companion` 与 `learn-by-practice`：

1. 触发、开场与上下文恢复；
2. 学习目标、资料和单元选择；
3. 学前预测与当前理解诊断；
4. 讲解、提问和纠错顺序；
5. 微动作、正式练习与提示梯度；
6. 编码练习中的测试与作品所有权；
7. 作品审查、修订和问题关闭；
8. 理解检查、迁移检查和完成门槛；
9. 暂停、收工、恢复与状态持久化；
10. 文章、课程档案、过程记录和下游 Skill 的衔接；
11. 用户确认点与各类文件的写入权限。

每一项先比较现状与设计取舍，再记录用户决定；未确认前不修改 Skill。
