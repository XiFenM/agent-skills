Memo Cards 把已经核验、值得反复强化的英语或技术材料整理为适配 Markji 3.8+ 的受管 Markdown 与 XLSX 文件集。它负责选材、拆卡、去重和本地发布，也能按明确请求通过墨墨官方 API 将卡片追加到指定自建牌组的指定章节。

## 什么时候适合使用

- 希望预览、创建、刷新或去重墨墨记忆卡。
- 已经有稳定的学习要点、真实英语错误、成熟文章或结构化学习记录。
- 希望把技术知识区分为稳定概念和带版本范围的实现事实。

制卡必须由用户明确提出。学习结束、其他 Skill 的建议或素材已经准备好，都不会自动触发制卡。

## 制卡流程

1. **确认范围。** 用户指定素材、目标卡片集合（collection）、目标文件，并说明采用默认的“精选”还是“完整转换”。完整转换仍只包含达到质量要求的内容。
2. **筛选素材。** Agent 检查结论是否稳定、来源是否可追溯、事实是否已经核验，以及内容是否值得间隔复习。猜测、冲突、遗留问题和未核验的时效信息只会出现在阻止原因中。
3. **整理卡片。** Agent 围绕单一回忆目标形成单点卡、机制卡或综合口述卡，并标明常青知识或版本范围。
   题面包含必要场景、对象、条件和作答目标；答案给出足够清楚的解释，使卡片在忘记原课堂细节后仍能
   独立复习。复杂答案按“结论／要点／边界”分层，由工具负责受控版式、逻辑身份、去重和格式校验。
4. **展示预览。** 用户会看到完整题面、答案与内容层级，延后、阻止、重复或冲突的候选，以及目标文件
   的准确差异和风险。简短目录只用于定位，不替代完整题答；预览不会只报告卡数或模板名。
5. **确认并保存。** 没有写入授权时停在预览。低风险新建可以沿用当次明确的保存请求；接管旧文件、人工修改、来源或模板变化、删除和跨文件刷新等情况，需要查看差异后再次确认。
6. **验证与导入。** 保存完成后，Agent 验证 Markdown 与全部 XLSX。用户可以选择模板后逐个上传 XLSX；也可以明确要求直接上传，由 Agent 展示远端目标和内容，再通过官方 API 创建并读回核验。

## 用户需要做什么

- 提供明确的素材范围，并在需要保存时选择准确目标。
- 决定精选或完整转换，检查哪些候选被纳入、延后或阻止。
- 对有风险的更新、冲突或旧文件接管确认准确差异。
- 手动导入时选择匹配模板并上传 XLSX；直接上传时，指定已有自建牌组和章节，并在本机配置请求凭据。

## 卡片怎样保持易读

“内容聚焦”指一张卡尽量考查一个明确的知识点，不要求题面和答案尽量短。Agent 会按单张、乱序复习
的情境检查：只看正面能否知道在讨论什么、已知条件是什么、需要回答什么；揭晓答案后能否理解结论
为什么成立，而不必回翻原始资料或寻找上一张卡。

影响作答的背景放在正面可见的字段中，例如具体算法任务、当前算子阶段、变量含义或必要的版本限制。
仅写“本课中”不足以重建场景，来源链接也不能承担题面解释。答案先给直接结论，再按需说明推理、步骤、
例子及边界；短标签和记忆锚点辅助回忆，不代替完整句的解释。

是否拆卡取决于包含几个独立知识目标，不由文字长度或折行次数决定。必要上下文应保留，无关铺垫可以
删除；清楚的一句话事实也无需刻意扩写。新建和旧卡审核都采用这一标准，补充背景时仍以已核验资料为
依据，不编造原来的学习场景、错误原话或实验结果。

卡片只使用少量固定语义色：绿色表示正确内容或结论，橙色表示边界，红色只表示已核验的真实错误，
灰色表示来源等元数据。Agent 不会把原始 Markji 标记写进卡片字段；公式、链接和多行结构都由工具从
受控内容生成。结论与边界的短标签可随卡片语言调整，但在同一 collection 中保持一致。

需要核对 `T`、`P`、`F`、`Choice`、`E` 或 `Pic` 的原始边界与示例时，可以查阅随 Skill 保存的
[《墨墨记忆卡「内容语法」说明》PDF](../../skills/memo-cards/references/markji-content-syntax.pdf)。这份
固定快照用于解释内容语法，不替代 Markji 当前的表格导入帮助或客户端实测。

## 产物与边界

本地产物是一个受管 artifact set：Markdown 保存来源、卡片身份、模板、差异审计信息和 XLSX 链接；每个实际使用的模板对应一个可上传的 XLSX，卡片数据不再复制进 Markdown。只有用户明确要求并成功完成 API 上传后，才能报告远端新增卡片。待复核（`review`）或已归档（`archived`）等状态只描述本地产物，不会自动更改 Markji 中已有卡片。

更新时，预览会同时显示 Markdown 的精确文本 diff，以及每个 XLSX 的创建、刷新、删除、行变化和哈希。旧版只含 Markdown／TSV 的受管文件不会被批量改写；只有用户以同一目标发起刷新、审阅迁移变化并确认后，才升级为新的 Markdown＋XLSX 形式。

原始对话、未作答问题、`[遗留]`、研究中的推断和存在冲突的事实不会直接制成正式卡片。软件事实发生变化时，通常会建立带新版本范围的后继卡，而不是静默改变旧卡含义。

当前环境没有提供经过校验的受管配置时，Agent 只能在对话中讨论和预览候选，不能猜测保存路径。此 Skill 不会上传媒体、覆盖或删除远端卡片、提交或推送 Git。

## 直接上传与安全配置

可以说：“把这些已核验材料制成卡片，保存后上传到我的某某牌组／某某章节。”Agent 会核对真实 ID，
展示名称、隐私状态、卡片全文及新增／跳过项目。已明确授权的准确目标和范围无需逐卡再次确认。
仅要求本地制卡时，不会自动上传。

从[官方凭证入口](https://open.maimemo.com/open/api/v1/tokens/openapi)获取 token 后，优先通过系统
凭据管理器注入 `MAIMEMO_API_TOKEN`。Linux／macOS 也可在本机终端运行
`python3 .agent-skills/skills/memo-cards/scripts/markji_api.py auth-set`，隐藏输入并保存到仓库外的
`~/.config/memo-cards/maimemo-token`，目录权限为 `0700`、文件为 `0600`。不要把密钥发到聊天、
写进仓库配置或命令参数。私有文件是权限保护的明文；需要加密存储时使用系统凭据管理器。
详细路径、远程机器配置、检查和轮换方法见[API 与密钥说明](../../skills/memo-cards/references/markji-api-upload.md)。

上传前需要从一张当前可正常渲染的真实卡片核实 `grammar_version`，不能根据 App 版本猜测。
上传器只追加，跳过完全相同的卡片，并把远端 ID 与摘要保存在仓库外的恢复回执中。中断时先核对结果，
不盲目重试；已有逻辑卡片内容变化或远端人工修改时停止，不覆盖旧卡。首次使用新语法还应在 Markji
检查代表卡的显示效果。

可用素材通常来自 `guide-learning` 已核验的理解或文章、`study-log` 中稳定的 `[要点]` 和 `[纠错]`，以及 `english-coach` 识别出的真实稳定语言问题。上游素材不携带制卡授权，用户仍需单独提出请求。完整组合方法见[学习类 Skill 组合使用指南](../learning-skills-user-guide.md)。
