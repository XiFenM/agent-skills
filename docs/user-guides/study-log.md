Study Log 用于从 Codex 或 Claude Code 会话中选择一段学习对话，并按需保存为精炼的学习过程记录或可追溯的可见文本。两种产物用途不同，隐私边界也不同。

## 选择记录类型

| 类型 | 适用情况 | 保存内容 |
| --- | --- | --- |
| 结构化记录（`structured`） | 日后复盘、保留纠错、整理高价值问答或准备制卡素材 | 学习者原始回答、误解、纠错、关键转折、高价值问题和遗留事项 |
| 可追溯文本归档（`raw`） | 审计、研究或需要逐轮查看当时可见对话 | 带来源、边界和校验信息的“可追溯可见文本对话” |

如果用户只说“保存这段对话”，Agent 会先确认需要哪一种。两种都需要时会分别生成，可追溯文本归档仍需单独确认。

## 共同流程

1. **确定来源。** 用户说明项目、客户端和目标会话。Agent 只发现当前任务相关的根会话，不查看无关会话。
2. **预览候选。** Agent 展示会话时间、消息数量、首尾内容、稳定消息边界和隐私风险类别。工具检测到的凭据和个人标识值会在预览中遮盖；检测并不穷尽所有风险，归档前仍需用户检查隐私和内容所有权。
3. **确认边界。** 用户选择需要保存的起止消息。存在多个会话或重复文本时，Agent 不会自行猜测。
4. **生成对应产物。** 结构化记录会先在仓库外临时提取材料，再整理为简洁记录并清理临时文件；可追溯文本归档会在用户确认来源、边界、状态、风险和私有目标后由工具直接生成。
5. **安全更新。** 已有结构化记录更新前会展示差异。可继续追加（`partial`）的归档只能向后扩展，转为最终封存（`final`）后不再覆盖。

## 用户需要做什么

- 选择结构化记录或可追溯文本归档，并确认会话、主题和消息边界。
- 保存结构化记录时选择准确目标；已有同一记录时审阅差异。
- 保存可追溯文本时确认可继续追加或最终封存、私有目录和隐私处理方式。
- 对凭据、个人信息或可能的专有内容作出选择；所有权或适用政策不清楚时，不应继续归档。

用户只需使用自然语言说明这些选择，不需要记忆脚本命令。

## 结构化记录

结构化记录保留学习过程中具有复盘价值的差异，通常使用 `[要点]`、`[纠错]`、`[转折]`、`[高价值问题]` 和 `[遗留]`。它不会复写完整教学正文，也不是知识权威、课程状态或掌握证明。

如果没有本地原始会话，但当前可见对话已经足够，只有结构化记录可以据此整理，并明确标注来源边界。

## 可追溯文本归档

这类产物只能准确称为“可追溯可见文本对话”。它默认排除 system、developer、reasoning、工具事件、客户端注入和附件正文，因此不是完整客户端会话，也不表示内容已经匿名化。

高置信度凭据默认阻止写入。用户可以优先缩小边界、改用结构化记录，或在明确选择后采用可复现脱敏或原样私存。可能的专有内容需要单独确认。首次保存没有隐式目录，用户需要选择一个 Git 工作树外的绝对私有目录；默认拒绝位于项目或 Git 工作树内的目标，也不会自动修改 `.gitignore`。

## 与其他 Skill 的边界

`study-log` 不修改课程状态、文章、卡片或 Git 历史。`guide-learning` 可以在暂停或结束处提议整理结构化记录，但得到用户同意后才会交接。`memo-cards` 可以使用稳定的 `[要点]` 和完整 `[纠错]`，不能直接使用 `[遗留]` 或可追溯文本对话。历史材料用于英语回顾时，由本 Skill 负责发现和选择会话，再由 `english-coach` 负责语言练习。

完整组合方法见[学习类 Skill 组合使用指南](../learning-skills-user-guide.md)。
