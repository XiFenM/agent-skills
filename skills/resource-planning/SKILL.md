# 学习资料收集与规划（周更 + 月底晋级评审）

两个流程属于同一条资料管线（流入 → 沉淀 → 晋级），共享条目格式、ID 规则和禁改清单，所以合在一个 skill。但它们之间有一道**刻意的硬隔离，是整套计划体系的地基，绝不因合并而模糊**：

> **周更只收集候选，绝不晋级**（不碰任何 `学习指引.md` / `进度.md`）；
> **晋级只在月底、由人拍板**（且不重新搜网，只用当月周报的 §晋级候选）。

## 模式路由

- 参数或用户话语含「周更 / 资料更新」→ **周更模式**
- 含「月底 / 晋级 / 评审」→ **月底评审模式**
- 不明确时问一句再动。

## 周更模式

触发语（惯例）：「请严格按 `计划/周更流程.md` 的规范，为本周执行一次全板块资料周更。」

**先读 `计划/周更流程.md`**——完整 SOP，精确且有硬规则，以它为准。执行要点：

- 输出：**恰好一个**新文件 `计划/周报/YYYY-Wxx.md`（周号用 `date +"%G-W%V"`）。目标已存在时默认不覆盖，先让用户决定补充还是停止。
- 派 2–3 个可用的并行子代理（按 SOP §4 Step 2 分板块），各自用可用的网页读取/互联网搜索工具扫订阅源与 arXiv 关键词（近 7 天），按 README §5 单条格式返回候选。
- 主会话汇总后，对既有各模块 `学习指引.md` 与历史周报**去重**，写周报，末尾列 **3–5 条 §晋级候选**。
- 订阅源清单以 `README.md §5` 为事实源；与某模块 `学习指引.md §长期订阅` 冲突时以 README 为准。
- **硬规则**：本流程绝不修改任何 `学习指引.md` 或 `进度.md`。

## 月底评审模式

触发语（惯例）：「请严格按 `计划/月底晋级评审.md` 的规范，对本月（YYYY-MM）做一次晋级评审。」

**先读 `计划/月底晋级评审.md`**，以它为准。执行要点：

- 输入只有当月各周报的 §晋级候选——**绝不重新搜网**。
- 每条候选按 SOP §3 的五问 rubric 打分，≥3 个 yes 进入「建议晋级」清单。先展示完整的晋级/拒绝/待定建议、得分与理由，**等用户确认后才执行任何编辑**。
- 每条晋级的编辑集（一条不多、一条不少）：
  1. 目标 `{module}/学习指引.md` — 字母后缀 ID 插入（如 `19a`），**绝不重编号**已有行；
  2. 该文件顶部 `## Changelog` — 追加一行；
  3. 晋级条目为 🟥 时 — `{module}/进度.md` 补对应行；
  4. 每条候选所在的本月源周报 — 追加 `> **状态**：✅/⏭/🔖 …` 注记（这是过期周报唯一允许的编辑）；
  5. `计划/进度总表.md` 月度复盘日志 — 一行小结。
- 替换类晋级（如 EAGLE-2 → EAGLE-3）：保留旧 ID 位置，注记 `（替代自 …，YYYY-MM-DD）`，**绝不删除旧条目**。

## 两模式共同硬边界

- 绝不编辑：`计划/主计划.md`、`计划/周更流程.md`、`计划/月底晋级评审.md`、非当月周报；当月周报也只允许追加状态注记。
- 图标只用注册表：🟥/🟨/🟩（优先级）、⬜/🟡/✅/⏭/🔖（状态），不发明新符号。
- 日期一律写绝对日期（`2026-05-10`，不写「本周日」）。
- Bash 里 CJK 路径加引号（`"计划/周更流程.md"`）。
