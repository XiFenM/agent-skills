## 1. 何时进入正式练习

先完成节点讲解、导师串讲和综合验收，再把已有证据对照每个目标所需的证据类型。

- 所需证据都已充分：跳过练习，直接结课确认。
- 缺独立实践、变式或实证证据：设计能补足该缺口的最小练习。不要为了形式安排"复现、边界、迁移、评估"的
  完整阶梯。
- 不引入与目标无关的复杂度、新的心智模型或隐藏要求；练习需要一项独立的新能力时，提议拆课。
- 非代码主题使用可观察的工件：推导、案例分析、设计说明、实验解释、批评或决策说明。

## 2. 练习约定

开始前停止讲解，一次性展示约定并请学习者接受：

1. **为什么做**：对应的目标，以及缺失的是哪类证据。
2. **你交付什么**：任务和学习者负责的核心产物。
3. **怎样算通过**：带编号的可观察验收项，以及各自的检查方式（测试、rubric、命令、解释、对照或实验）。披露
   全部必需的行为和边界，不必展开每个 fixture 的内部实现。
4. **文件边界**：你写／我维护／我只读／本次不动。
5. **求助如何影响证据**：可以随时自然地求助；透露了关键解法只影响相应范围，之后用新变式恢复。
6. **非目标与完成门槛**：可选项单列；全部必需验收项通过、阻塞问题全部关闭即为完成。

| 标签 | 含义 |
| --- | --- |
| 你写 | 学习者创建或修改；Agent 可以读、运行和 Review，不代改 |
| 我维护 | Agent 在约定内创建、修复、运行和记录，不逐个文件确认 |
| 我只读 | Agent 只检查，不创建或修改 |
| 本次不动 | 不在本次范围内；纳入前重新确认 |

使用仓库相对路径、受限模式或逻辑工件名，不把宽泛目录当作隐式授权。受管 context 中的 `practice-*` 映射只是
候选位置和写入上限，不替代约定中逐项列出的路径与边界，也不能把可选项变成必需项。

记录约定时只保存：编号、版本号（从 1 开始）、目标与缺口、任务、交付物、验收项、文件边界、可选项，以及
学习者接受的时间点。约定的语义变化时（目标、交付、验收项、文件边界或可选项），版本号加一，展示变化并
重新取得接受；纯排版调整不改版本。原约定有歧义时标为"约定澄清"，不归咎于学习者；澄清改变了完成门槛时，
仍须重新接受。

## 3. 所有权与测试驱动

- 学习者拥有核心实现；Agent 拥有测试、rubric、fixture 和记录。只有测试、fixture 或验证工具的设计本身是
  学习目标时，才把它们交给学习者；不要把"学习者写测试"当成代码练习的默认附加目标。
- 代码练习的顺序：
  1. 学习者接受约定；
  2. Agent 在"我维护"的路径建立最小、可读的验收测试，覆盖公开行为、不变量、边界和必要的错误行为，不泄露解法；
  3. 运行并确认失败来自预期缺口（expected red），而不是环境、fixture 或测试本身的问题；
  4. 把测试路径、运行方法和简短的用例说明交给学习者，不要求第二次确认；
  5. 学习者从 red 推进到 green。
- 测试有缺口或写错时，Agent 在授权范围内修复并如实报告；不因验证失败接管学习者的核心工件。
- 已有行为本来就正确、无法产生有意义的 expected red，或主题不适合可执行测试时，改用基线、rubric、对照或
  证明检查，并说明 expected red 不适用。

## 4. 实验与 benchmark

- **学习者**：结果出现前给出有机制依据、可以被结果推翻的预测；结果出现后解释证据支持什么、不支持什么。
- **Agent**：设计并维护实验方法与 harness——按待验证的结论选择预热、同步、重复次数、运行顺序、资源配置、
  控制变量、主要指标、结果格式，以及"支持／否定／证据不足"的事前判据，并在运行前简要说明设置思路。
- 方法保持最低充分：除非结论或预期噪声确实需要，不自动加入统计检验、置信区间、profiler、大规模扫描或固定
  性能阈值。功能正确性另有独立证据；不断言某个配置必然最快，预测与结果不符也不算练习失败。
- 只有实验设计、harness 实现、参数校验或统计推断本身是学习目标时，才把相应部分交给学习者。方法会扩大成本、
  依赖或硬件使用时，先修订约定。

## 5. 求助与独立证据

- 学习者独立尝试期间，只报告约定、验证结果和证据差距；一次失败、沉默或耗时较长不会自动升级帮助。
- 学习者求助后，先用一句话诊断是概念、执行、环境还是精力问题，再给最低必要的帮助，由弱到强：重述不变量
  并帮助定位 → 指向相关概念或来源 → 更小的类比，或拆成一个小步 → 伪代码或接口骨架（保留要验收的核心选择）
  → 只有学习者明确要求时才完整示范或接管。不向学习者暴露层级编号，不要求固定的求助措辞。
- 透露了关键分解、算法、核心公式、伪代码、具体修复或完整解法时，相应范围的独立实践证据失效。只记录三件事：
  透露到什么程度、影响哪些验收项或工件、Agent 是否写了学习者的核心工件。然后用一个更小、表面不同但原理
  相同的新变式，在无提示的情况下恢复证据。重述约定、报告失败证据或修复 Agent 自己的工件不算透露解法。
- 在聊天中展示答案，不等于授权修改学习者的文件。

## 6. Review 与问题跟踪

先确认对照的是学习者已接受的约定版本，再检查学习者产物和相称的验证。按以下优先级 Review：

1. 必需验收项与概念正确性；
2. 边界、失败行为和结果可复现性；
3. 清晰度、可维护性或性能，仅限已纳入完成门槛的部分；
4. 约定外的观察，明确不阻塞。

每轮向学习者报告：结论与最小验证证据、新增或变化的问题、最多三个当前动作、Agent 自行处理的验收问题。
不建立逐轮 Review 历史表。

需要跨轮跟踪的问题只记：编号、对应的验收项或目标、严重度（阻塞／非阻塞）、状态（未关闭／已关闭／延后）、
一句证据。同一根因只记一条并原地更新。

- 修改后只有复验通过才关闭，并附一句关闭证据。
- 阻塞问题要延后，须经用户同意并修订约定。
- 约定外的发现保持为观察，未经同意不升级为门槛；非阻塞问题默认不影响结课。
- 所有阻塞问题关闭后停止正式 Review，不因工程润色或可选项延长练习。
- 断点只指向第一个可执行的动作。

## 7. 三类证据与结课

每个目标在开课时声明需要哪几类证据；不在结课时临时降低标准，也不在未授权时新增。

| 证据 | 最低要求 |
| --- | --- |
| 理解 | 独立讲清中心模型和设计理由，指出一个关键边界或取舍，并完成一个没讲过的迁移、诊断或口述 |
| 实践 | 完成学习者负责的核心工件并通过验收，阻塞问题已关闭，能解释一个重要的验证，完成一个无提示的小变式 |
| 实证 | 结果出现前的可证伪预测；Agent 的方法写明环境、版本、输入、对照和判据且可复现；学习者能说明结论支持什么、不支持什么以及剩余的不确定性；性能结论另有独立的正确性证据 |

默认选择：概念或源码理解类目标需要理解证据；实现类目标需要理解和实践；涉及真实设备、版本或性能结论时
再加实证。综合验收已经提供的理解证据直接复用；由 Agent 准备实验方法、学习者负责预测与解释的实验，可以
满足实证而不要求实践。

结课时按目标逐项列出：所需证据类型、证据链接、判断（充分／不足）；再列出未关闭的阻塞问题、帮助影响是否
已恢复、非阻塞余项和建议。用户确认后才一次写入结课结论，按 [state-records.md](state-records.md) 移动或删除
断点；不自动开始下一课，也不自动进入可选内容。独立 Session 只关闭练习、保存会话级证据，不写 Lesson 结论。
