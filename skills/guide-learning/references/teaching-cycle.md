# Teaching cycle

在规划或继续结构化教学、核对必要前置、设计理解检查、补差或执行跨节点综合验收时读取本参考。
一次简单答疑只取解决当前问题所需的部分，不为形式完整运行整套流程。

## Prepare the teaching unit

先确定本轮要形成的能力，不要把“读完文件”或“结束会话”当成教学目标。

- 对独立 Session，写出一个短主题标签和本轮可观察结果，不自动建立 Lesson。
- 对已授权 Lesson，使用既定的 2–4 个目标和 required mastery 维度；不要在教学中静默增加目标。
- 对一次答疑，把目标缩成当前问题能解决的最小边界。
- 标出学习者已有的可靠 evidence、未知前置和可能改变教学路径的分叉。
- 把用户选择的 teaching spine 与事实权威分开；需要处理来源角色时读取 `source-authority.md`。

当主题包含两个独立心智模型、两个可分别关闭的 gate、新的前置能力，或验证方式从理解／正确性转为
独立实证研究时，提议拆分。不要用一场长会话掩盖 Lesson 边界。

## Check only necessary prerequisites

先从已验证 mastery、既有工件、近期 Session evidence 和用户明确陈述中核对前置。不要固定执行课前
考试，也不要把缺少记录等同于不会。

仅当一项前置同时满足以下条件时提问：

1. 当前证据不明确；
2. 它会实质改变讲解起点、目标范围或练习设计；
3. 学习者可以依据已有知识作答。

一次只问一个最有区分力的问题。把“不知道”视为有效定位信息，不视为失败。

- 小缺口：在进入当前节点前做最短补充，不新增目标或 mastery gate。
- 独立能力缺口：说明它为何需要单独验收，提议建立前置 Lesson，并让用户决定是否调整范围。
- 不影响当前路径的未知：记录为 observation 或暂不处理，不阻塞教学。

不要要求学习者预测尚未讲解、也无法从已确认前置推导的新事实。只在已经建立机制模型后做迁移预测，
或在实验结果出现前保存可证伪预测。

## Map key nodes

先给一张很短的全局图，再进入细节。全局图只回答：

- 当前能力解决什么问题；
- 由哪些关键节点组成；
- 节点之间的数据、控制、状态或论证关系；
- 最终需要什么证据。

把关键节点划为能分别讲清和检查的最小单元。一个节点通常包含一个中心关系、一个重要边界和一个
可观察检查；不要按段落数或文件标题机械切分。

累计覆盖以下内容，但不要塞进一次长讲：

- 动机与中心模型；
- 关键术语和组件关系；
- 数据、控制、状态或论证流；
- 约束、边界、反例或失败条件；
- 验证方法与适用限制；
- 与本课目标有关的取舍或迁移点。

让一个完整案例跨多个微循环逐步成形：每个节点只补上该案例当前所需的一部分，并保留前面成果；不要
用彼此孤立的小例子取代贯穿案例。所有节点完成后，再统一收束案例的全链路、边界和验证证据。

## Run the micro-cycle

对每个关键节点执行以下循环：

1. **讲**：按学习者现有水平解释机制、关系和边界；使用一个足以承载模型的具体例子。
2. **挖**：邀请追问；只扩展会帮助当前节点或修复已暴露前置的内容。
3. **探**：提出一个基于刚讲内容或已确认前置的理解检查。
4. **答与判**：让学习者完整表达，不抢答，不把沉默自动解释为能力缺陷。理解无误时跳过“补”和
   “再探”，直接进入“做”；只有发现差距才进入补差分支。
5. **补（仅有差距）**：只讲当前回答与目标之间的差值。
6. **再探（仅补差后）**：改变条件、例子或问法；不要让学习者机械重复标准答案。通过后进入“做”。
7. **做**：要求一个轻量复述、举例、自测、映射或推导工件。
8. **验**：即时纠正；证据充分时推进，否则缩小节点或回补前置。

“做”只巩固当前节点，不自动成为正式练习，也不需要仓库工件。让轻量工件保持几分钟内可完成；若
它需要完整文件、正式 Review 或跨会话修订，先判断是否已经进入正式练习。

## Choose adaptive checks

每个节点选择一个当前最有区分力的形式：

- 用自己的话复述关键关系或不变量；
- 追踪数据、控制、状态或论证流；
- 比较相近概念，指出边界或失败条件；
- 改变一个已讲条件并预测结果；
- 把陌生案例映射到当前模型；
- 根据现象诊断失效节点；
- 完成最小推导；
- 给出一个能满足或反驳规则的例子。

不要堆叠同义问题。选择题、术语回忆或照着刚给出的答案复述可以辅助定位，但不能单独证明理解。
检查不得依赖隐藏事实；如果学习者需要尚未提供的信息，先承认题目无效并修正检查。

让检查匹配目标：

| 目标类型 | 优先检查 |
| --- | --- |
| 概念或源码理解 | 中心模型、控制流、边界、相似概念差异、版本锚点 |
| 设计或实现 | 不变量、接口行为、失败诊断、条件变式 |
| 实验或 benchmark | 学习者事前预测与结果解释；Agent 提供测量方法、控制变量和证据判据 |

除非实验设计、benchmark harness 或统计推断本身是已授权目标，不要要求学习者决定 warm-up、同步、
重复次数、运行顺序、指标、噪声处理或支持条件。Agent 应在正式练习契约内按 claim 选择最低充分方法，
向学习者解释这些设置如何隔离变量与限定结论；学习者只需理解与当前结论直接相关的关键边界。

## Repair gaps

先判断差距属于概念、执行、环境还是精力，再采取最低必要动作。

- 概念差距：重述不变量，换一个更小例子，再用不同条件复查。
- 执行差距：把动作缩成一个可观察的小门，不替学习者完成核心选择。
- 环境差距：在授权范围内修复 Agent-owned 环境或验收工件；不要把它记录为 learner finding。
- 精力或节奏问题：缩小当前节点、降低信息密度或暂停；不要以更强提示替代休息选择。

单次答错、测试失败、沉默或耗时较长不会自动升级帮助。持续困难时缩小节点或补最短前置，不重复
整段长讲。学习者主动求助时，按 `practice-review-mastery.md` 的帮助边界处理 material assistance。

## Synthesize and assess

覆盖所有关键节点后，先让学习者合成完整心智模型，再执行小型跨节点综合验收。通常使用 2–4 个
整合问题，但以最低充分证据为准，不把题数当作配额。

综合验收至少覆盖：

1. 中心模型或完整流程；
2. 一个关键边界、反例或相似概念差异；
3. 一个未直接讲过的同构迁移、条件变化或诊断；
4. 实证型目标所需的学习者事前预测，若适用；具体测量方法由 Agent 在正式练习契约中建立，除非实验
   设计本身就是目标。

不要把多个节点的原题简单拼接。让问题迫使学习者连接节点，并保留足够陌生度来区分理解与记忆。
回答有差距时只补差值并换题复查；综合验收可以短暂回到微循环。

## Branch by evidence

把综合验收结果映射到目标和 required mastery 维度：

- 概念证据已满足时，直接记入概念维度；不要为形式完整重复练习。
- 仍缺独立实践、变式或实证证据时，进入能补足该缺口的最小正式练习。
- 所需证据均充分时，进入 mastery gate；不要自动增加 optional extension。
- 独立 Session 只形成会话级 evidence。需要长期 mastery 时先授权创建或并入 Lesson。

在进入正式练习前停止教学微循环，读取 `practice-review-mastery.md`，一次性展示完整契约并请求接受。
