# Teaching cycle

设定目标深度、开课、划分节点、讲解、提问、补差、串讲和综合验收时读取本参考。一次简单答疑只取解决当前
问题所需的部分。讲解应达到什么样子，以 [teaching-exemplars.md](teaching-exemplars.md) 为准。

## 1. 设定能力与目标深度

先写出本轮要形成的能力；"读完某个文件"或"结束会话"不是教学目标。

目标要写到理解层，而不只停在操作层。以同一个机制为例：

| 层级 | 学习者能做到 |
| --- | --- |
| 操作 | 按步骤算出某个量、复述流程 |
| 理解 | 解释为什么需要它、在什么条件下成立、换一种设计会怎样 |
| 迁移 | 用到没讲过的系统或配置上，并向面试官讲清取舍 |

目标只停在操作层时，补上理解层；工程岗位或面试准备默认要求到迁移层。计算类目标只在估算本身是岗位
能力时保留（例如通信量、显存、算力或带宽估算），并同时要求解释结论。

先读学习者画像：已经熟悉什么、目标深度、偏好的表达顺序；再结合已有证据和用户当轮的陈述。画像是必备输入，
仓库里没有时先按 [repository-adaptation.md](repository-adaptation.md) 第 6 节访谈并建立，再设定目标。已熟悉的
内容只做对照，不从头讲；画像写明没有基础的领域，不默认学习者认识其中的名词。

- 已授权 Lesson 使用既定的 2–4 个目标和各自所需的证据类型；不在教学中静默增加目标。
- 独立 Session 写一个短主题标签和本轮可观察的结果，不自动建 Lesson。
- 一次答疑把目标缩成当前问题能解决的最小范围。
- 出现独立的心智模型、可分别关闭的练习、新的前置能力，或验证方式从理解转为独立实证研究时，提议拆课。

## 2. 开课导入与全流程骨架

首次进入结构化 Lesson，或开始有多个依赖节点的独立 Session 时，先用一段连贯叙述回答：为什么学（背景与
核心矛盾）、将学会什么、路线怎样走、学到什么程度算完成。

- 核心矛盾真实存在时再讲；不要为了结构硬造"旧方案失败、新方案胜出"的故事。
- 给出之后可以回看的全流程骨架：输入与输出、主数据流或控制流、阶段之间传递的关键状态。骨架属于全貌，
  不能为了"简短"而省略；局部推导和 API 细节放到对应节点。
- 说明本轮在路线中的位置和后面的关键点。
- 有教学主线资料（教程、文档、论文、源码）时先指路：资料在哪里，本课对应其中哪些文件、章节或页面；线上资料
  给出与所用版本一致的地址；说明哪些建议课前读、哪些随节点读。不要让学习者自己去找“这一课讲的是资料里的
  哪一段”。
- 不逐项宣读目标、证据类型、记录路径和权限；这些属于开场的控制信息，一两行即可。

按范围缩放：

- 无漂移地恢复已开始的课：一句话挂回当前位置和已建立的模型，然后直接继续。
- 一次答疑或窄问题：直接回答，或只给足以定位问题的局部框架。
- 用户或资料在当轮已经建立全貌：只补缺失的连接。
- 用户要求跳到某个节点：照做，按需一句话交代它在全局中的位置。

学习者反馈全貌不清时，先补整体关系和节点间的连接，再回到局部；读过资料或答对局部题不等于理解了整条链路。

## 3. 核对必要前置

先从已有证据判断：已确认的掌握、已有工件、近期记录和用户陈述。不做固定的课前考试，也不把"没有记录"
当作"不会"。只有同时满足以下条件才提问：

1. 当前证据不明确；
2. 答案会改变讲解起点、范围或练习设计；
3. 学习者凭已有知识可以回答。

一次只问一个问题，"不知道"是有效信息。小缺口在进入节点前最短补齐；构成独立能力的缺口，说明原因并提议
前置 Lesson，由用户决定；不影响当前路线的未知暂不处理。

## 4. 划分节点与贯穿案例

- 节点是能单独讲清的最小单元：通常包含一个中心关系和一个重要边界。不要按段落数或文件标题机械切分。
- 选一个贯穿全课的案例。每个节点只补上它的一部分，最后在串讲中合成完整链路；不要用一堆互不相关的小例子。
- 用小规模把机制讲清之后，给出对应的真实规模：真实模型配置、真实张量形状、真实带宽或显存量级，让学习者
  知道这个机制在真实系统里意味着什么。
- 全课累计覆盖：动机与核心矛盾，关键组件的关系，数据、控制或状态流，边界与失效条件，验证方式，与目标
  相关的取舍和迁移。不必塞进一次长讲。

## 5. 讲一个节点

按讲解标准的阶梯组织：机制 → 设计理由 → 真实系统 → 边界 → 表达与迁移，按目标深度取层。

- 有教学主线资料时，节点开头指出它对应资料的哪一部分、建议先读还是讲完再读；讲解补充了主线没有的内容时，
  说明它来自哪里。
- 先给结论，再给理由和细节。一个节点讲完，学习者应能用一两句话说出它"是什么、为什么"。
- 表达顺序服从学习者偏好：能跟随通式的学习者，先给符号关系、标注维度并映射到源码，再按需代入数字；
  初学者可以先用实例建立关系。符号先定义含义、轴、单位和适用域；不同维度即使取值相同也用不同符号。
- 节点依赖某个 API、数据类型或抽象时，先讲清它的语义、最小用法和选择理由，再读依赖它的代码；不要扩成手册。
- 算法、算子和多阶段程序：先写未分块、未优化时的完整数学，再讲实现怎样分解、每个并行单元负责什么；
  阶段之间传递的状态说明谁产生、谁消费、为什么需要（包括为反向传播保存的量）；区分存储类型与累加精度，
  说明选择理由。
- 区分数学要求、实现限制和性能选择；来源没有说明的作者动机或收益标为推断，必要时按
  [source-authority.md](source-authority.md) 做一手核验。
- 适用边界集中写成一句；只有会改变判断的限定才写进正文。
- 讲完留出追问空间；追问只展开服务当前节点或修复已暴露前置的内容。

## 6. 设计检查题

检查题要让学习者**用自己的模型推理**。优先选择层级高的题型：

| 层级 | 题型 | 例 |
| --- | --- | --- |
| 迁移 | 把模型用到没讲过的系统或配置 | "把在线 softmax 的合并规则用到分块 Attention 上，每个块需要额外保留什么？" |
| 取舍 | 比较方案，按场景选择并说出代价 | "FlashAttention 的反向为什么选择重算注意力矩阵，而不是保存它？" |
| 诊断 | 从现象定位原因 | "profiler 中看不到 All-to-All，可能有哪些原因？分别用什么证据区分？" |
| 预测 | 改一个条件，预测结果并说明理由 | "把块大小翻倍，片上存储占用和可并行的块数会怎样变化？" |
| 解释 | 说明设计的必要性，去掉会坏在哪 | "分块 softmax 为什么必须保留每行的最大值和指数和？" |
| 口述 | 60–90 秒讲清一个机制 | "向面试官解释 MoE 中 EP 与 TP 的取舍。" |

- 计算题只在估算本身是目标能力时使用，并要求解释数字的含义；不要用计数、查表或学习者已熟练的算术充当检查。
- 选择题、术语回忆或照着刚给的答案复述只能辅助定位，不能单独证明理解。
- 不堆叠同义问题；检查不得依赖没讲过的隐藏事实。
- 出题前自检：
  1. 符号都已定义；
  2. 影响答案的条件都已写明——数据在哪、布局、单位、表示域（是否已缩放、归一化或取对数）；
  3. 只依赖已讲内容和已确认的前置；
  4. 判对标准明确。
- 题意含糊是出题问题：先澄清，再换一道题复查受影响的范围，不把澄清前的歧义记为学习者的缺陷。

实验或 benchmark 类目标，检查重点放在学习者的事前预测和事后解释。除非实验设计本身就是目标，不要要求学习者
决定 warm-up、同步、重复次数、运行顺序、指标或判据；这些由 Agent 在练习约定中选择并解释。

## 7. 调节节奏

- 默认连讲 2–3 个紧密相关的节点，再问一道高层级的题；节点本身复杂或是常见误区时，可以单独检查。
- 学习者连续两次首答正确：扩大节点，把题目提升一个层级，省去复述类练习。
- 回答有差距：只补当前差值，换条件或例子复查；不重复整段长讲。
- 持续困难、长时间沉默或明显疲劳：缩小节点、补最短前置、降低信息密度，或提议暂停；不要用更强的提示代替休息。
- 学习者明确调节节奏（"讲快点""多讲少问""多出题"）时照做，并在之后保持。
- 轻量练习（复述、举例、映射、推导）只在检查题没能提供证据或学习者需要巩固时使用，几分钟内可完成；需要
  完整文件或跨会话修订的，已属于正式练习。

## 8. 补差

先判断差距类型，再采取最低必要的动作：

- 概念差距：重述核心关系，换一个更小或更贴近学习者经验的例子，再用新条件复查。
- 执行差距：把动作缩成一个可观察的小步，不替学习者做核心选择。
- 环境差距：在授权范围内修复 Agent 负责的环境或验收工件，不记为学习者的问题。
- 精力或节奏：缩小节点、降低密度或暂停。

单次答错、测试失败、沉默或耗时较长都不会自动升级帮助。学习者主动求助时，按
[practice-review-mastery.md](practice-review-mastery.md) 的帮助规则处理。

## 9. 串讲与综合验收

所有节点讲完后：

1. **导师串讲**：沿同一个贯穿案例，亲自把完整流程、节点之间的依赖、关键状态的产生与用途、主要取舍和边界
   串一遍，并落到真实系统的规模。串讲是讲解而不是考试，不要在串讲中提前回答验收用的新变式。
2. **综合验收**：通常 2–4 题，至少覆盖：
   - 中心模型或完整流程；
   - 一个关键取舍、边界或相近概念的区别；
   - 一个没讲过的迁移或诊断；
   - 一道 60–90 秒的口述题；
   - 实证类目标另加结果出现前的可证伪预测。
3. 题目要迫使学习者连接多个节点，保留足够的陌生度来区分理解与记忆；不要把各节点的原题简单拼接。已有证据
   覆盖的部分减少或跳过，题数以证据是否充分为准，不是固定配额。
4. 回答有差距时只补差值并换题复查，必要时短暂回到节点讲解。

## 10. 按证据分流

- 所需证据已充分：直接进入结课确认，不安排形式性的练习。
- 仍缺独立实践、变式或实证证据：停止讲解，进入能补足该缺口的最小正式练习，先读
  [practice-review-mastery.md](practice-review-mastery.md)。
- 独立 Session 只形成会话级证据；需要长期的结课结论时，先授权建立或并入 Lesson。
