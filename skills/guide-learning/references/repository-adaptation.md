# Repository adaptation

把计划、课程账本和断点映射到仓库文件，选择写入路径，解释受管 context，或在仓库没有学习结构时建立最小结构时
读取本参考。不要硬编码任何消费仓库的路径。

## 1. 先看再映射

先读仓库指令、目录结构、已有的学习记录和当前状态，检查有没有未提交的用户工作；不覆盖、移动或顺手整理无关
内容。依次回答：

- 哪里已经承载长期目标和范围？
- 哪里已经承载当前能力的设计、实验或证据？
- 哪里记录用户确认的实际用时？
- 是否已有唯一的恢复游标？
- 哪些文件只是汇总视图、文章、日志、卡片或原始对话？
- 哪些路径允许 Agent 创建或维护？

根据内容和仓库约定判断职责，不只看文件名。一个文件可以用稳定的小节承载多个对象；多个文件不能同时拥有同一
个活动事实。

## 2. 受管 context

生成副本中的 `.agent-skills-context.json` 只在 manager、Skill 身份和 schema 完全匹配时使用，不要自行修补或
部分解释未知字段。

- `repository_fact_refs`：只读事实的位置，例如仓库指令、学习者偏好、预算、资料目录、验证说明、历史证据。
  角色名不会把资料自动提升为教学主线、事实权威或掌握证据。
- `record_mappings`：计划、课程账本、断点和练习工件的候选位置。它只提供位置，不保存状态，也不改变本 Skill
  的字段和写入规则。映射应指向不随每课变化的稳定文件或目录；当前课由断点指向，不靠修改配置来切换。
- `allowlist.write_paths`：materializer 核验过的写入上限，不是写入授权。

先核对映射位置的实际内容是否承担所声明的职责。映射与仓库指令、已有的唯一来源或未提交的用户工作冲突时，保持
只读并请用户选择，不按配置另建第二份记录。context 缺失时按第 3 节正常发现；context 损坏或身份不符时停止使用
其全部 locator，请用户重新 materialize。materializer 不读取资料正文；实际读取本地混合资料时按
[material-reading.md](material-reading.md) 检查本次选中的文件。

## 3. 发现顺序

1. 仓库指令中明确声明的学习状态、课程或记录位置；
2. 已有的计划、课程、进度或断点结构；
3. 可以复用的设计包、实验记录、研究记录或项目文档小节；
4. 仓库已有的 notes、docs 或学习约定；
5. 用户明确指定的位置；
6. 以上都没有时，经用户授权的最小新结构（见第 6 节）。

找到合适的位置就停止搜索；不要因为通用结构更整齐而另建第二套。不要把 README、入口说明或 Agent 指令文件
变成状态账本，除非仓库明确赋予它们这个职责。

## 4. 单一写入者

| 事实 | 唯一位置 | 不应放在 |
| --- | --- | --- |
| 长期目标、范围、候选课程 | 计划 | 课程账本、日志、文章 |
| 本课目标、来源、事件、练习约定、问题、结课结论 | 课程账本 | 汇总视图、原始对话、卡片 |
| 当前位置与下一步动作 | 断点 | 历史日志、汇总视图、计划、课程正文 |
| 全局预算 | 已有长期计划中的唯一预算来源 | 断点、事件 |
| 资料的预计投入 | 稳定的课程资料或资料治理文件 | 实际进度记录 |
| 用户确认的实际用时 | 原始进度来源 | 派生汇总、课程证据 |
| 周期性汇总 | 派生汇总视图 | 断点、原始事件 |
| 知识叙述 | 文章或其他知识产物 | 计划、断点 |
| 误解、纠错与关键转折 | 按需生成的学习记录 | 结课结论的替代品 |
| 原始可见对话 | 经用户确认的原始归档 | 课程状态、正确结论 |

写入前比较语义差异。派生汇总只在仓库已有的周期性触点更新，不随每次学习同步；过期的汇总不能反过来覆盖原始
事实。文章、学习记录、原始对话和卡片可以链接课程和证据，但不保存当前阶段、下一步动作或独立的结课结论。

## 5. 路径与授权

- 首次创建计划、课程账本、断点或其他 Agent 维护的状态文件前，向用户说明拟用路径及其职责。足够具体的开始
  请求可以授权目标和范围，但不自动授权未说明的路径；受管 mapping 省去猜测，不省去这一步。
- 使用仓库相对路径，限定到具体文件、稳定小节、受限模式或逻辑工件名；不把宽泛目录当作所有权。
- 遵循仓库的命名、语言和格式；不改配置、CI、依赖或公共接口，除非另行授权。
- 把现有文件列为"你写"或"我只读"时，不因 Agent 能读取就假设可以修改。练习中"我维护"的路径在练习约定中
  单独授权，不在开课时预授权全部可能的工件。
- 路径有歧义、且选择会改变事实来源或覆盖用户工作时，停下来询问；不要用"临时"的第二份记录绕过选择。

## 6. 没有约定时

只有仓库完全没有可复用的约定时才新建：

1. 只建当前范围需要的对象：一次答疑零写入；独立 Session 通常只要事件和必要的断点；持久 Course 才建计划和
   真实授权的课程账本。
2. 提出一个与仓库风格一致的最小路径和职责，获得授权后按 [state-records.md](state-records.md) 的字段直接写入。
3. 不附带 README、索引、模板、初始化脚本或占位文件；没有实际数据的可选内容不写。
4. 记录这个路径为什么成为唯一来源，避免之后另建副本。

## 7. 旧记录

迁移时保留历史证据，不批量改写已完成的课程、旧的 Skill 名称或路径、原始对话，或已被哈希引用的正文；把旧
内容标为历史，为新的活动状态选定唯一来源。停止双写时：找出旧文件之间重复的当前位置、下一步、会话记录、
时长或结课结论；选定一个活动来源，让其他位置停止更新并保留为带日期的历史；在断点记录迁移后的同一语义位置
和下一步动作；确认恢复无漂移后再继续教学。在真实的暂停点做最小适配，不必等整门课结束，也不触碰无关的用户
工作。
