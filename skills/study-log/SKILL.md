# Study Log

将学习过程导出为仓库内一一配对的结构化记录与可追溯可见文本。始终通过自然语言理解用户意图；不要要求用户记忆或输入脚本命令。

## 首次启用时提示用户说明

在当前对话第一次启用本 Skill 时，用一条简短、非阻塞且不带独立标题或卡片的提示建议用户先浏览本
Skill 的 `docs/user-guides/study-log.md` 和组合指南 `docs/learning-skills-user-guide.md`；说明它们介绍
交互流程、用户需要参与的环节和授权边界。

定位本地文档时，只按顺序检查三个候选根：当前 `SKILL.md` 所在 Skill 目录的上两级目录、当前工作区
仓库根、当前工作区仓库根下的 `.agent-skills`。把实际存在的文件解析为绝对路径并提供可点击链接，不
搜索其他目录。没有本地文件时，改为提供[本 Skill 公开说明](https://github.com/XiFenM/agent-skills/blob/main/docs/user-guides/study-log.md)
和[公开组合指南](https://github.com/XiFenM/agent-skills/blob/main/docs/learning-skills-user-guide.md)。

用户没有要求先暂停阅读时继续处理当前请求；不要求用户确认，不在同一对话重复提示，也不创建文件
记录是否已经提示。同一对话已经提供组合指南时只补本 Skill 说明；同一回复首次启用多个学习 Skill 时
合并为一条提示，并且只列一次组合指南。

## 路由意图

- 正式导出以一组记录为单位：结构化记录用于复盘和制卡，配对的可追溯文本用于回查原话。用户只要候选、预览或解释时不写文件。
- 用户要求整理或保存学习记录时，确认同一主题的来源与边界，以及两种文件的仓库内位置；原文的隐私与专有内容风险仍须单独说明并取得确认，不能把整理请求当作原文披露许可。
- 已有一种记录时，只补用户授权的对应项，不覆盖已存在文件或静默扩大原文范围。用户明确只要其中一种时遵从其范围，并说明缺少配对项，不宣称完整导出已完成。
- 不自动把旧记录全部配对；缺少可核验原文时保留历史缺口，不伪造对话。

## 仓库内配对规则

- 全部导出目标必须位于当次 `--project` 内，不再使用用户级私有 archive root 或环境变量决定输出位置。
- 结构化记录为 `<记录目录>/<主题文件名>.md`，唯一配对原文为同级 `<记录目录名>-raw/<同一文件名>.md`；例如 `模块/log/x.md` 对应 `模块/log-raw/x.md`。同名和原文元数据中的 `structured_record` 共同定义一一对应，不依赖文件数量或会话续段数量猜配对。原文目录不得嵌套在结构化 collection 内，以免被制卡或英语回顾的递归读取清单纳入。
- 新结构化记录在头部链接对应 `../log-raw/` 文件（按实际目录名计算）；raw 由脚本写入结构化文件的相对回链。旧结构化记录若已作为卡片的哈希来源，可保留字节原样，按规范路径与 raw 绑定字段配对。只有消费仓库与当前请求明确了已有索引及维护范围时才补迁移入口，不自动创建或修改索引。
- 原文按结构化主题边界组织。一个主题跨多份源会话或旧归档时，以可核验的来源分段合并；一个旧归档涵盖多个主题时按明确消息边界拆分。迁移必须保留消息 ID、正文、规范化与脱敏身份及原归档来源。
- 临时提取也放在仓库内专用暂存目录，使用完即删除，不作为配对记录或提交内容。保存到仓库内不等于授权 Git stage、commit、push 或公开披露，也不自动修改 `.gitignore`。

## 共用流程

1. 明确项目、客户端和会话。只使用用户指定或当前任务直接相关的会话；不要查看无关会话。
2. 用 `scripts/study_log.py list` 发现根会话，再用 `preview` 获取 source SHA-256、稳定消息 ID、边界候选和隐私风险类别。
3. 边界不明确时向用户确认。优先使用稳定消息 ID；文本片段重复时不得猜选。
4. 确定结构化记录及同名 raw 目标，完成下方所需操作；导出后调用 `verify-pairs` 验证绑定与内容完整性。详细调用契约和错误处理见 [references/extraction-contract.md](references/extraction-contract.md)。

消费仓库若通过统一 version 2 配置提供 `.agent-skills-context.json`，只把其中
`structured_targets`（包含派生的 `paired_raw_path`）与 `allowlist.write_paths` 当作记录的合法候选范围。不要遍历目标目录；该
context 不授予读取 collection、保存某次记录、覆盖文件或选择具体目标的权限。配置格式与无配置降级见
[references/context-contract.md](references/context-contract.md)。会话 source、消息 boundary、临时提取
位置和精确配对目标始终由当次 CLI 调用与用户确认决定；配置只给目录规则，不给来源或授权。

## Structured：结构化学习过程记录

1. 来源、边界和新目标明确时，用户的生成请求即构成授权；存在多个合理会话或主题边界时先澄清。
2. 带预览所得 source SHA-256 调用 `extract`。让脚本在项目内 `.study-log/scratch/` 创建临时材料；显式临时路径也必须在同一项目内。结构化模式可以在明确告警下忽略唯一残缺尾行，中间坏行仍须停止。
3. 从临时材料中保留学习者原始回答、误解、纠错、高价值问题和关键转折；不复写完整教学正文、课程状态或 mastery。按 [references/log-format.md](references/log-format.md) 写入消费仓库配置或用户当次明确指定的位置。
4. 配置中的 target root 只是静态范围，不是当次写授权。新记录仍须由用户本轮请求选择精确目标；已有同一逻辑记录时，先展示 diff 并取得明确确认，不得静默覆盖人工编辑。
5. 完成蒸馏后删除临时材料。结构化记录是过程材料，不是知识权威或课程状态。

## Raw：可追溯可见文本对话

始终准确称为“可追溯可见文本对话”。不要称为完整客户端 Session，也不要声称它已经匿名化。脚本默认排除 system、developer、reasoning、工具事件、客户端注入和附件正文。

写入前合并展示并确认：

- provider、会话和 source SHA-256；
- 起止消息及首尾预览、消息数；
- `partial` 或 `final`；
- 凭据、个人信息和可能的专有内容风险；
- 结构化记录与同名 raw 的仓库内目标位置，以及进入 Git 历史的潜在披露风险。

然后调用 `archive`，并遵守以下规则：

- 必须传入 `--structured-record`，指向同一仓库内已存在的结构化 Markdown；脚本按同名规则导出到其同级 `-raw` 目录。`--output` 不能改到任意位置；旧私有 root 配置只可用于定位历史文件，不再作为新导出的回退路径。
- 不从公共配置读取会话目录、source、boundary 或授权；目录规则不能替代对精确目标与内容的确认。
- 高置信度凭据默认阻止写入；仓库内导出只允许 `block` 或经确认的可复现 `redact`，不再允许原样写入凭据。也可缩小边界或只预览结构化候选。保留已确认的专有叙述不代表可以提交或公开。
- 公司代码、内部 API、未公开硬件／性能数据等可能的专有内容需要单独确认；所有权或政策不清楚时停止。普通个人信息给予警告并纳入确认。
- 拒绝仓库外、其他仓库、Git 管理目录和符号链接逃逸目标。仓库内文件不要求被 Git 忽略；是否跟踪和提交由用户决定，原有覆盖、目标 SHA 和 final 生命周期防护继续生效。
- raw 始终严格解析 JSONL。source 或目标 SHA-256 与预览不一致时停止并重新预览／展示 diff。
- 新建 partial 后只原位推进结束边界。更新前读取现有元数据和正文，把新增消息范围、消息数、结束边界及状态变化作为 diff 展示；用户确认后，使用相同 `archive_id` 和当时审阅的目标 SHA-256 原位更新。`partial → final` 只能单向发生，final 不再覆盖。
- 不手工润色生成的消息正文。边界或隐私处理不正确时，调整规则并重新生成。

## 迁移已有归档

使用 `migrate-preview` 展示原文件 SHA、结构化配对目标、消息分段、数量和目标摘要；确认后用同一请求与 digest 执行 `migrate`。迁移生成新的配对归档并保留来源元数据，不原地改写旧 final。工具要求原消息恰好分配一次，禁止丢失、重复或跨项目拼接。原文件保留到新目标、消息守恒和配对验证全部通过；只有用户要求移动时才删除明确列出的旧文件。不要迁移用户排除的仓库。

## 失败与边界

- 会话不存在而当前上下文足够时，只能在 `structured` 中把来源标为“当前可见上下文（无本地原始日志）”；否则请用户提供目标材料，绝不补造。
- 没有受管 context 时仍可发现、预览并临时提取用户本轮选择的会话，也可在聊天中生成 structured candidate；默认不猜消费仓库路径且零仓库写入。只有用户本轮明确指定精确目标时，才按一次性授权处理。
- 对话源只读。此 Skill 不修改课程状态、文章、卡片或 Git 历史，也不负责提交产物。
- `memo-cards` 可以消费稳定的 `[要点]` 和 `[纠错]`；`[遗留]` 不直接制卡。
