# 完成前语言审查（课程网页）

目标：页面文字**口语化、生动、生活化**，像在跟学习者当面说话；**先立后破**（先定前提直说确定因果，边界集中放到边界层或批注，不在机制段堆叠防御性免责句），不牺牲条件、因果、数字、来源和 caveat；同时确认本段发挥了网页的图解与动态交互优势，不是把纯文字和表格直接搬进 HTML。

这是完成前的硬门：没有通过审查，不 `add`、不声称页面完成。

## 什么时候审

1. **任何含正文的 `new` / `add` 之前**：审这个片段。纯代码、表格、部件片段可以不审语言，但要确认没有夹带新正文。
2. **结课、最后一页、或声称“页面完成”之前**：审整页可见正文（开课导入 + 各段正文 + 串讲/验收），不只审新片段。
3. **改错或重写正文之后**：只复查改动段；如果改动跨段，复查受影响范围。

## 怎么审：Gemini 核心直走子 Agent，非 Gemini 宿主远程优先

按下面的前置分流与顺序执行，每一步都不许跳过或假装通过：

### 0. 前置分流（主 Agent 已是 Gemini 核心）

如果当前主 Agent 本身以 **Gemini** 为核心，**不需要调用 ZenMux API**，直接跳到第 2 步使用**宿主只读子 Agent**审查（ZenMux 默认链路本身就是 Gemini 4，外发无额外跨模型收益）。若由统一脚本调用 `zenmux_review.py`，传 `--host-model gemini` 或设 `VIVID_LANGUAGE_HOST_MODEL=gemini`，脚本会以退出码 2 直接引导走第 2 步。

### 1. 远程模型（非 Gemini 宿主首选）

1. 当主 Agent 不是 Gemini（如 GPT / Codex / Claude 等），调用启用中的 `vivid-language` Skill 的 `scripts/zenmux_review.py`，把**可见正文**交给它，不要给整页 HTML、脚本或样式：

   ```bash
   python3 <vivid-language>/scripts/zenmux_review.py --kind page draft.md
   ```

   配置、模型链和隐私说明见该 Skill 的 `references/remote-review.md`。用户没有 `ZENMUX_API_KEY` 时脚本退出码为 2，不要追问 Key，直接进第 2 步。

2. `verdict` 为 `PASS`：记录 `语言审查：PASS（ZenMux / <model>）`，可以继续。
3. `verdict` 为 `REVISE`：先改 blocking，再把改动段送一次；`fact_risk` 不为“无”时逐条核对数字、版本和引用。
4. 退出码 2 或 3、脚本不存在、宿主没有 Python：都算跳过或远程不可用，进第 2 步；退出码 1 是输入问题（空、超长、路径错），修输入再跑，不要当成通过。

### 2. 子 Agent（Gemini 宿主首选，或远程不可用兜底）

1. 主 Agent 调宿主提供的子 Agent 工具（如 `subagent`）；子 Agent 只读审查，不改文件。
2. 子 Agent 读 `vivid-language` 的 `references/language-contract.md`（课程网页体裁）和 `references/plain-language.md`；读不到时用本文件末尾的 10 条 rubric。
3. 输入是**可见正文**（另附一句列出本段包含哪些交互部件或图解，便于核对是否纯文字搬运），不是整页 HTML、脚本或样式：片段审片段；终审给导入 + 各段正文。
4. 子 Agent 返回 `PASS` 或 `REVISE`；`REVISE` 必须列 blocking，每条给出原文、问题、建议改法，不重写全文。
5. 主 Agent 修完 blocking，再把改动段交给子 Agent 复查；`PASS` 后才能 `add` 或声称完成。
6. 记录 `语言审查：PASS（子 Agent，<审查范围>）`。

### 3. 都没有

不要静默跳过，也不要声称“语言审查通过”。按下面的 rubric 自审，明确告诉用户“未独立审查”，并请用户确认是否接受；只有用户明确接受后，才继续 `add`，且最终指路和结课时仍要标注“未独立审查”。

## 审查 prompt（子 Agent 用，可直接粘贴）

```text
你是课程网页的语言审查子 agent，只审查，不改文件。

先读：
- 启用中的 `vivid-language` Skill 的 `references/language-contract.md`（课程网页体裁）
- 同一 Skill 的 `references/plain-language.md`

目标：页面文字口语化、生动、生活化，像在跟学习者当面说话；先立后破（先定前提直说确定因果，边界集中放边界层或批注）；不牺牲条件、因果、数字、来源和 caveat；同时确认该段没有退化成纯文本加表格。

审查对象：
<粘贴可见正文，或给出片段文件路径；另附一句本段配置的图解/交互部件清单>

只返回以下结构：
- verdict: PASS 或 REVISE
- blocking: 每条 {原文, 问题, 建议改法}
- non_blocking: 同上，可为空
- 事实风险: 改写可能改变的技术结论/数字（没有就写“无”）

blocking 只放：丢失条件/因果/caveat、编造事实、仍是教材腔、未立先破的防御性免责刷屏（反复穿插“不代表/不能说明/不外推/不声称”等打断概念建立）、空泛配平句、让读者不知道谁在做什么、以及整段讲解（含状态流转/对比/参数取舍）退化为纯文字加静态表格而零图示零交互。
不要因为“可以更俏皮”就判 blocking。
```

## Rubric（10 条）

- [ ] 开头或段落先给场景、对象、问题，而不是定义或目标清单？
- [ ] **先立后破**：前提一次交代清，机制与设计理由直说确定因果，没有在建立概念途中反复贴“不代表/不能说明/不外推”等防御性免责句？
- [ ] 边界集中在「边界」段或批注里，优先说明“换到 X 条件会怎样”而不是连串否定？
- [ ] 像在跟学习者说话，而不是“本节将讨论/需要注意的是”？
- [ ] 有一个具体例子、数字或日常比喻？比喻标了“哪里不像”吗？
- [ ] 主语、条件、因果、caveat 完整吗？有没有为了短删信息？
- [ ] 一段一个中心关系，长句拆开了吗？
- [ ] 没有空泛配平句、制作说明（“示例/示意图/仅供参考”）或元数据标签？
- [ ] 技术事实、数字、来源没有被“生动化”改掉？
- [ ] 发挥了网页媒介优势（配了对应的交互部件或清晰图解），不是纯文字墙或静态表格搬运？

## 报告怎么说

预览、指路和结课里只写一句结论，三种来源分开写：

- `语言审查：PASS（ZenMux / google/gemini-4-hydrogen）`
- `语言审查：PASS（子 Agent，整页可见正文）`
- `语言审查：未独立审查（自审，用户已确认接受）`

不能只报页数或样式名，也不能把“未审”写成“通过”。
