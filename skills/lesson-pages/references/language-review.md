# 完成前语言审查（课程网页）

目标：页面文字**口语化、生动、生活化**，像在跟学习者说话；但不牺牲条件、因果、数字、来源和 caveat。

这是完成前的硬门：没有通过审查，不 `add`、不声称页面完成。

## 什么时候审

1. **任何含正文的 `new` / `add` 之前**：审这个片段。纯代码、表格、部件片段可以不审语言，但要确认没有夹带新正文。
2. **结课、最后一页、或声称“页面完成”之前**：审整页可见正文（开课导入 + 各段正文 + 串讲/验收），不只审新片段。
3. **改错或重写正文之后**：只复查改动段；如果改动跨段，复查受影响范围。

## 怎么审

1. 主 Agent 调宿主提供的子 Agent 工具（如 `subagent`）；子 Agent 只读审查，不改文件。
2. 子 Agent 读 `vivid-tech-writing` 的 `references/language-contract.md`（课程网页体裁）和 `references/plain-language.md`；读不到时用本文件末尾的 8 条 rubric。
3. 输入是**可见正文**，不是整页 HTML、脚本或样式：片段审片段；终审给导入 + 各段正文。
4. 子 Agent 返回 `PASS` 或 `REVISE`；`REVISE` 必须列 blocking，每条给出原文、问题、建议改法，不重写全文。
5. 主 Agent 修完 blocking，再把改动段交给子 Agent 复查；`PASS` 后才能 `add` 或声称完成。

## 审查 prompt（可直接用）

```text
你是课程网页的语言审查子 agent，只审查，不改文件。

先读：
- 启用中的 `vivid-tech-writing` Skill 的 `references/language-contract.md`（课程网页体裁）
- 同一 Skill 的 `references/plain-language.md`

目标：页面文字口语化、生动、生活化，像在跟学习者说话；但不牺牲条件、因果、数字、来源和 caveat。

审查对象：
<粘贴可见正文，或给出片段文件路径>

只返回以下结构：
- verdict: PASS 或 REVISE
- blocking: 每条 {原文, 问题, 建议改法}
- non_blocking: 同上，可为空
- 事实风险: 改写可能改变的技术结论/数字（没有就写“无”）

blocking 只放：丢失条件/因果/caveat、编造事实、仍是教材腔、空泛配平句、让读者不知道谁在做什么。
不要因为“可以更俏皮”就判 blocking。
```

## Rubric（8 条）

- [ ] 开头或段落先给场景、对象、问题，而不是定义或目标清单？
- [ ] 像在跟学习者说话，而不是“本节将讨论/需要注意的是”？
- [ ] 有一个具体例子、数字或日常比喻？比喻标了“哪里不像”吗？
- [ ] 主语、条件、因果、caveat 完整吗？有没有为了短删信息？
- [ ] 一段一个中心关系，长句拆开了吗？
- [ ] 没有空泛配平句、制作说明（“示例/示意图/仅供参考”）或元数据标签？
- [ ] 技术事实、数字、来源没有被“生动化”改掉？
- [ ] 适合页面阅读，不是聊天碎片或整页术语墙？

## 没有子 Agent 时

不要静默跳过，也不要声称“语言审查通过”。按上面的 rubric 自审，明确告诉用户“未独立审查”，并请用户确认是否接受；只有用户明确接受后，才继续 `add`，且最终指路和结课时仍要标注“未独立审查”。
