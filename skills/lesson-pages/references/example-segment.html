1分块：让 S 和 P 只活在片上

FlashAttention-2 论文第 3.2 节，建议讲完再读

结论把 Q 按行切成块分给不同的线程块，每个线程块沿 K、V 的列块循环；S 和 P 每次只算出 Br×Bc 的一小块，用完即弃，显存里从不出现 N×N 的矩阵。

机制一个线程块负责 Q 的一个行块 Q_i（B_r 行）。它把 Q_i 留在片上，依次读入 K、V 的每个列块 K_j、V_j（B_c 列），算出局部分数 S_{ij} = Q_i K_j^{\top}/\sqrt{d}，立刻用它更新这些行的输出累加，再丢掉 S_{ij}。不同行块之间互不依赖，可以并行。

为什么这样设计Attention 的矩阵乘算力并不紧张，慢在搬运：N = 8192 时，单头一份 FP16 的 S 就有 8192 × 8192 × 2 字节 = 128 MiB，朴素实现要写一遍、读一遍，P 再来一遍。分块把这四趟 N² 级的显存读写换成片上运算，代价是 softmax 不能再一次看到整行，这正是节点 2 要解决的问题。

真实系统FlashAttention-2 把并行放在批、头和 Q 的行块三个维度上：一个线程块负责一个行块，所以长序列、小批量时仍有足够多的线程块占满 GPU。块大小 Br、Bc 受片上存储和寄存器限制，头维 d 越大，每块能放的行越少。

来源：FlashAttention-2 论文 arXiv:2307.08691 v1 第 3.2 节。128 MiB 按定义计算。

边界分块只改变数据在哪里、按什么顺序算，不改变数学结果；浮点累加顺序不同，逐位结果可能有微小差异。

2在线 softmax 为什么要保留两个统计量

FlashAttention-2 论文第 3.1 节的算法 1，建议先读

结论分块处理一行时，只要保留当前最大值 m 和指数和 ℓ，就能在看到新块后把之前的结果换算到新的最大值基准上，最终得到与整行 softmax 完全相同的结果。

机制处理新块 S_j 时，三样状态这样更新。旧的 ℓ 和 acc 都以旧的 m 为基准，先乘上缩放因子 \alpha = \exp(\sA{m} - \sA{m}_{\text{new}})，就换到了新基准。

\begin{aligned} \sA{m}_{\text{new}} &= \max\bigl(\sA{m},\ \operatorname{rowmax}(S_j)\bigr) \\ \alpha &= \exp\bigl(\sA{m} - \sA{m}_{\text{new}}\bigr) \\ \sB{\ell}_{\text{new}} &= \alpha\,\sB{\ell} + \operatorname{rowsum}\bigl(\exp(S_j - \sA{m}_{\text{new}})\bigr) \\ \sC{\mathrm{acc}}_{\text{new}} &= \alpha\,\sC{\mathrm{acc}} + \exp(S_j - \sA{m}_{\text{new}})\,V_j \end{aligned}

下面用一行 12 个分数、每块 4 个走一遍；V 简化成每个位置一个标量，让 acc 也是一个数。

把这四行写成代码，对一个 Q 行就是下面这个循环（V 同样简化成每个位置一个标量）。指向或点按一条说明，它讲的那几行会亮起来。

import math

def attention_row(scores, values, block=4):
    m, l, acc = -math.inf, 0.0, 0.0
    for start in range(0, len(scores), block):
        s = scores[start:start + block]
        v = values[start:start + block]
        m_new = max(m, max(s))
        alpha = math.exp(m - m_new)  # 第一块时 m = −∞，alpha = 0
        p = [math.exp(x - m_new) for x in s]
        l = alpha * l + sum(p)
        acc = alpha * acc + sum(pi * vi for pi, vi in zip(p, v))
        m = m_new
    return acc / l, m + math.log(l)  # 输出 O 与 logsumexp L

为本课写的参考实现 · Python 3.12 标准库可运行

  1. 先求新的最大值，再算把旧状态换到新基准的缩放因子；第一块时 m 是 −∞，α 自然是 0，不用特判。
  2. ℓ 和 acc 都先乘 α 换基准，再加上本块的贡献。
  3. 整行看完才归一化；同时返回 L = m + log ℓ，留给反向。用图 2.1 的 12 个分数调用，得到的 O 与最后一步的读数相同。

小例子只是为了看清规则。真实规模下一行有几千个分数，按 Bc = 64 或 128 分成几十个块，但每行随身带的状态始终只有 m、ℓ 两个 FP32 标量和长度为 d 的 acc，与 N 无关。

为什么这样设计减去最大值是为了数值稳定：指数对较大的输入会迅速溢出（FP32 在输入约 88 时溢出，FP16 约 11 时就溢出），减去行最大值后所有指数都不超过 1。但最大值要看完整行才知道，所以需要“先用当前最大值，之后再修正”的在线规则。只保留 m 不够，没有 ℓ 就无法归一化；只保留 ℓ 也不够，没有 m 就无法把不同块的指数换到同一基准。

真实系统反向传播需要 P，但保存 N×N 的 P 正是前向想避免的。FlashAttention 只为每行保存 L = m + log ℓ，只占 O(N) 空间；反向按块重算 S，再用 P = exp(S − L) 恢复概率，用重算换显存和带宽。

来源：FlashAttention 论文 arXiv:2205.14135 第 3.1 节；FlashAttention-2 论文 arXiv:2307.08691 v1 第 3.1 节。

边界块大小受片上存储和寄存器限制；因果掩码下完全被遮住的块可以直接跳过。这些改变性能，不改变数学结果。

面试怎么讲约 60 秒

FlashAttention 不减少计算量，而是减少显存读写：它从不把 N×N 的注意力矩阵写回显存。做法是分块加在线 softmax，每行只维护最大值和指数和，看到新块时把旧结果缩放到新的最大值基准。反向时只保存每行的 logsumexp，按块重算注意力矩阵，用计算换带宽和显存。
