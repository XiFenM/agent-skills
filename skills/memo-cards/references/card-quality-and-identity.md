# 卡片质量与身份

## 素材准入

正式卡片必须同时满足：结论稳定、来源可追溯、事实已核验、适合反复强化。先把每个候选分流：

- A：高价值、会反复使用或能防止高成本错误；必须进入本批预览和可导入集合。
- B：存在稳定迁移价值，但重要性或复发概率较低；可以进入精选或明确延后。
- C：低价值、一次性措辞或不适合间隔复习；不进入正式卡片。
- blocked：raw 对话、`[遗留]`、未作答题、猜测、冲突、未核验的时效事实和研究中结论。保留原因，不把它们改写成确定事实。

默认精选，不为达到数量目标制造卡片。消费配置可以提供软目标；它只控制本批新增 B 卡的注意力负担，不截断 A 卡、不计算既有卡刷新，也不替代 Markji 的复习调度。用户明确要求完整转换时，纳入全部合格 A／B 卡。

## 稳定逻辑身份

逻辑身份只由以下四项组成：

1. 领域；
2. 稳定回忆目标；
3. 考查方式；
4. 事实范围。

日期、来源路径、题面措辞、例句和场景不进入身份。相同目标跨日出现时复用 canonical 卡并提高优先级；题面或例句改善不创建新身份。含义、产出方向、能力要求或版本范围真正变化时才创建新卡。让工具计算 `logical_id`，不要由 Agent 仿造 hash。

跨文件命中同一 ID 时，不自动改旧文件：相同内容只报告 canonical 卡并抑制新行；内容有实质改善时提出独立的跨文件刷新，重新取得授权。

## 英语卡

- 纠错卡只记录真实、稳定的错误。合法但不够地道或语域不合适的表达不得伪装成红叉错误。
- 无真实错误时使用主动产出卡；只有存在稳定、可迁移边界时，才把表达差异做成 B 级辨析卡。
- 选择题使用 2／3／4 选项模板。挖空只用于上下文可唯一确定的 1–3 个词或词形，且不是默认卡型。
- 每张原子卡只考一个目标。不要让例句或场景暗中增加第二个考点。

## 技术卡的三个正交维度

### 时效范围

- 常青：不依赖内部符号、默认值、目录、具体版本或单一 commit 的稳定概念。
- 版本快照：函数、类、目录、进程数、路由公式、具体 codegen 行为、源码观察或固定 commit 支撑的结论。至少记录产品与版本或 commit。

不确定时使用快照。软件事实改变时建立后继卡，不用新答案静默覆盖旧版本问题；仍与学习基线相关的旧快照保留，其余进入本地 archived。

### 学习层级

- 原子卡：一个判断、映射、前提或单一对比轴。
- 机制卡：一条不可拆的 2–5 步闭合因果链。若用 `depends_on` 表达已有子卡基础，只能引用同 request 内
  eligible、已核验且 active 的 A／B 原子／机制卡；manifest 保存逐依赖内容 SHA-256。
- 综合口述卡：组合 2–5 张本轮 eligible、已核验且 active 的 A／B 原子／机制子卡，支持 45–90 秒回答，
  并给出 3–5 个评分锚点。manifest 保存逐子卡内容摘要；任一子卡漂移时，同一目标事务中的口述卡进入
  `review` 并在发布前再次确认，跨文件依赖则报告为必须独立处理的 `dependent_reviews`。不得引入子卡没有
  核验的新事实。

子卡实质漂移时，依赖它的机制卡和综合卡都进入复核；同目标 request 内自动转为 `review` 并要求再次确认，
跨文件依赖统一报告为必须独立处理的 `dependent_reviews`。

### 本地生命周期

允许的主路径是 `candidate/research → active → review → active | archived`。`review` 是持久状态：原 request 中的 `active` 不构成解除；恢复 `active` 必须提供本轮复核的 `review_resolution.summary`，查看精确 diff，并以 `confirmed` 发布。未验证观察、疑似 bug 和能力猜想交回 `guide-learning`；可以制作“如何验证”的常青方法卡，但不能制作未决事实卡。只有反复出现且能预测未来错误的个人误区才进入独立误区集合，并指向规范主卡。

`review` 与 `archived` 只描述本地受管暂存状态，不代表 Markji 远端已暂停、替换或删除。

## 上游素材包

上游 bundle 只能携带 schema、生产者／预期消费者、逻辑仓库／主题范围、带版本或 fingerprint 的来源引用、稳定条目、事实状态与 blocked 原因。拒绝授权标记、写入命令、任意 prompt、私有 archive root、绝对目标路径和自动执行标记。bundle 到达后仍须用户自然语言明确提出制卡。
