# 卡片内容与版式

版式服务于回忆，不补救过载。先决定一张卡只考什么，再决定怎样显示；题面同时追问多个判断、步骤或
边界时，优先拆卡或改成合格的机制卡／综合口述卡，不把长文本缩小、染色后继续塞进一张原子卡。

## 先过拆卡门槛

- 问题只包含一个明确动作和一个回忆目标，删去不影响作答的背景、铺垫和来源说明。
- 问题应短促到能一眼读完。大号题面连续自动折行是诊断信号：先改写或拆卡，不用更多样式掩盖。
- 答案先给可独立成立的结论，再列必要要点，最后单独说明适用条件、例外或失效边界。
- 一条不可拆的 2–5 步闭合因果链可以保留为机制卡；需要组合 2–5 张子卡时使用综合口述卡。

典型失效信号包括：大号问题连续自动折行；答案成为没有显式结论、要点和边界的一整段；直到末尾的
锚点或来源才提供唯一的视觉层级。出现任一信号时，先重新检查回忆目标、措辞和拆卡。字符数与折行数
不设通用硬阈值，因为语言、模板和终端宽度都会改变实际显示。

## 设计依据

- [Markji 官方团队关于密集卡与卡片引用的说明](https://markji.discourse.group/t/topic/57)把“看起来累”
  视为拆分信号，建议把密集内容拆成更小、更聚焦的卡片，再用卡片引用保留关联。
- [SuperMemo 的知识表述二十条规则](https://www.supermemo.com/en/blog/twenty-rules-of-formulating-knowledge)
  支持最小信息、优化措辞，并把来源保留为回查元数据而非默认背诵内容。
- [Mautone 与 Mayer 的 signaling 研究](https://doi.org/10.1037/0022-0663.93.2.377)表明，有限的结构
  信号可以帮助读者识别材料组织。这里据此把少量标签和颜色用作组织线索；这是跨情境的设计推论，不是
  对某种卡片版式学习效果的保证。版式仍不能替代准确内容、主动回忆、拆卡和复习安排。

## 默认内容层级

短答案可以保持一行。复杂答案按下列顺序使用工具生成的受控结构块：

1. `lead`：一条能够直接回答问题的结论；工具只把短标签显示为绿色粗体。标签默认为“结论”，可以按
   卡片语言覆盖。
2. `point`：每行一个必要要点或步骤，使用 `•` 和短粗体中性色标签；标签表达维度，不重复正文。
3. `display`：可选的整行公式或图片，不与普通行内内容混排。
4. `boundary`：一条条件、例外或失效边界；工具只把短标签显示为橙色粗体。标签默认为“边界”，可以
   按卡片语言覆盖。

通常按 `lead → point/display… → boundary` 排列，只保留回答当前问题所需的块。工具在 lead 后、
boundary 前保留一个空行，其余每块独占一行；不要用连续空格、手写换行或重复 emoji 伪造布局。锚点
用于压缩复述线索，不能替代结论、步骤和边界。

题面与答案之间保留答案线；答案层级结束后再显示锚点、场景或来源。来源使用灰色弱化，只写足以回查
的人类可读短标签，例如文档名加小节，或产品加版本。绝对路径、完整 hash 和审计细节留在 manifest；
只有复习时确实需要打开的公共资料才生成链接。

## 少量一致的语义色

- 绿色只表示正确表达、直接结论或关键锚点。
- 橙色只表示条件、例外和失效边界。
- 红色只表示已核验的真实错误或明确危险项，不用作普通强调。
- 灰色只表示场景、版本和来源等次要元数据。

正文默认使用普通文字；优先靠拆分、顺序、标签和留白建立层级。不要为每个要点分配颜色，不叠加无
语义的前景色、背景色、粗体和字号。

## 受控内容而非原始语法

普通短字段使用单行字符串。公式、链接、已有媒体／卡片 ID 和多行答案结构都通过 request 的结构化
`content` 交给工具编译：简单组合使用 `parts`，分层答案使用 `blocks`；两者不能同时出现。`blocks`
推荐包含 2–6 个 `lead`、`point`、`display` 或 `boundary` 对象，绝对上限为 8；每个对象内部继续
使用受控 `parts`。`point` 必须带短 `label`；`lead` 与 `boundary` 可以覆盖默认短标签。所有 block
标签都不超过 20 个字符；可按卡片语言选择，但同一 collection 保持同一套语义标签。`lead` 必须位于
首位，`boundary` 必须位于末位。具体形状见[受管 Markdown 与 XLSX 合同](markdown-xlsx-staging.md)。

分层结构只写入模板中占位符独占一行的 `content` 字段。若一个字段已经被模板的 `T`／`P` 包裹、位于
Choice 选项，或和图标前缀共享一行，工具只接受普通字符串或纯 text parts；不要在“锚点”“正确／
错误”“选项”等嵌入位置塞入 blocks、公式、图片、链接或媒体。这样可以避免跨行样式、Markji 嵌套和
“整行元素”被前缀破坏。

Agent 不在任何普通字段、`parts` 文本或 block 标签中手写 `[T#…]`、`[P#…]`、`[F#…]`、
`[Choice#…]`、`[E#…]` 或答案线。模板 registry 与工具独占 Markji 语法、颜色、换行和组合校验；无法
用当前受控结构安全表达时停止并报告，不回退到原始语法注入。

## 已核验的 Markji 语法边界

以下边界来自[随 Skill 保存的《墨墨记忆卡「内容语法」说明》PDF](markji-content-syntax.pdf)；它们
约束工具生成的内容，不授权 Agent 直接拼接语法：

- `T` 是行内文字样式，不支持跨行；多个参数用英文逗号分隔，单 `!` 表示文字色、双 `!!` 表示背景
  色。颜色代码只支持小写，`up` 与 `down` 不能同时出现。复杂叠加虽然可解析，但不应成为默认版式。
- `P` 是整行文字样式；PDF 示例确认其可包含受支持的行内样式与行内元素。只把它用于短题面或短标签，
  不把长段落整体做成大号标题。
- `F` 是行内挖空，不支持跨行，也不能嵌套重点标记。只用于上下文唯一确定的 1–3 个词或词形。
- `Choice` 块内部只有选项，题干是块前的普通文字；每个选项独占一行。传统写法用 `* ` 标正确项、
  `- ` 标错误项；Markji 3.8.00+ 的 `ans` 参数可以直接指定答案字母。选项可含重点标记，不能含挖空。
  本 Skill 只由工具生成已登记的 2／3／4 选项 `ans` 形式。
- `E` 是整行公式，双井号后为 KaTeX；PDF 确认客户端 3.8.00 已完整支持。`Pic` 也是整行元素。公式或
  图片必须由结构化 part 生成、独占渲染行，不与普通行内 part 混排，也不嵌进 `T`。分层答案用
  `display` block 承载恰好一个公式，或一个／多个图片。

`---` 是题面与答案的整行分隔。所有这些语法都属于内容渲染层，不改变卡片的逻辑身份、事实范围、
质量等级或生命周期。
