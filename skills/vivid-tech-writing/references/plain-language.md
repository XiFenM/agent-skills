# 口语化与生活化：把“讲义”改成人话

用户说“太书面”“太像教材”“能不能更口语”“打个生活里的比方”时，读这一份。它是 [language-contract.md](language-contract.md) 的口语化子集；教学、页面、卡片的完整体裁规则见契约。

先说边界：口语化不是段子化，也不是把术语删掉。它主要改三件事：**先说什么、用什么句子、拿什么作锚点**。技术限定、数字、caveat 都要留下。

API 参考、规范、事故报告、法规不要硬套这一套；它们走 clarity-first，最多把定义讲顺，不要加故事和悬念。

## 四个动作

### 1. 先给一句话答案

难节开头，先用一句话说清“到底在干什么”，再展开步骤或公式。

例：

> 一句话：把重要通道的权重放大，再把输入除回去；数学上不变，但量化器看到的权重变了。

不要一上来就给 $D=\operatorname{diag}(d_1,\ldots,d_K)$。先让读者拿到“人话版”，公式才有落点。

### 2. 给一张流程/阶段图

读者卡住，往往不是不懂某一句，而是不知道整体走到哪。用箭头把阶段画出来：

```text
校准输入
  ↓
统计每个通道的激活大小
  ↓
搜索缩放系数
  ↓
权重乘缩放 → 量化 → 存整数码
  ↓
前一层除缩放（或折进参数）→ 运行时相乘
```

图不必漂亮，但要能回答“现在我读到哪、下一步去哪”。

### 3. 用一个日常物件当主线比喻

选读者每天用的东西，映射**结构**，不映射情绪。一个主比喻贯穿一节，2–3 个短比喻辅助，不要一段换一个。

好用的日常锚点：

| 日常物件 | 映射什么 | 边界 |
|---|---|---|
| 尺子 | scale 是格距，zero point 是“0 刻在哪” | 尺子连续，整数码离散；尺子没有舍入规则 |
| 记账 | 一边乘 4，另一边除 4，总账不变 | 记账不涉及舍入误差；量化有 |
| 全班合影 | 一个 2 米 2 的人逼着镜头拉远，矮个子只剩几个像素 | 照片像素均匀，量化码间隔由 s 决定 |
| 全班/每行/每四人一把尺子 | per-tensor / per-channel / group | 尺子不用存储，scale 要存；尺子不会因为一个人变长 |
| 考试平均分 | MSE 小不等于关键题做对 | 考试有主观题，MSE 只是数值平均 |
| 装修效果图 vs 真装修 | fake quant 仿真 vs 真实部署 | 效果图是视觉，仿真是数值 |
| 楼层编号（1 楼 vs G 楼） | zero point 的偏移 | zero point 不只是命名，它改变重建值 |

用法：先给比喻，再给“它哪里不像”，最后回到数字/公式。**比喻负责“为什么”，数字负责“是多少”。**

### 4. 把两个容易混的东西并排放

读者说“不明白”，很多时候是两个东西共用一个词。用一张表：

| 符号/阶段 | 是什么 | 什么时候用 | 最后在哪 |
|---|---|---|---|
| $d_k$ | 通道缩放系数 | 量化前 | 折进前一层 |
| $s_g$ | 组量化步长 | 量化时 | checkpoint 的 scales |

或者：

| 阶段 | 权重侧 | 输入侧 | 目的 |
|---|---|---|---|
| 搜索 | $W\cdot s\to Q\to /s$ | 原 $X$ | 模拟补偿，算误差 |
| 部署 | $Q(W\cdot s)$ → 存整数码 | $X/s$ | 真正跑 |

并排表比一段长解释有效，因为读者能横向对比。

## 比喻的三条规矩

1. **映射结构，不映射气氛。** 好比喻能让读者推出一个你没说的事实；只说“像”不够，要说“因为共享什么结构”。
2. **每个比喻标边界。** 加一句“它哪里不像”。不标边界的比喻，读者会用它推出错误结论。
3. **控制数量。** 一篇 2000 字文章，2–3 个主比喻，最多 4–5 个短比喻。不要同一域反复用；已经用了两张照片比喻，就换一个考试平均分。

## 口语化的句子手术

| 书面 | 口语 |
|---|---|
| 本节将讨论…… | 这一节就看…… |
| 需要注意的是…… | 这里有个坑…… |
| 由于……因此…… | 因为……所以…… / 直接说因果 |
| 可以实现…… | 你可以…… |
| 具体而言…… | 举个例子…… |
| 该方案具有较高的可维护性 | 改一行不用动三个文件 |
| 对性能进行了优化 | 从 800ms 降到 120ms |

其他：

- 长从句拆成两拍：先给现象，再给解释。
- 允许一句话成段；允许“对，但……”“先别急……”这种口语转折。
- 多用“你/我们”，但不要每句都加；技术文档可以零人称。
- 不要为了口语加“其实/说白了/懂的都懂”；这些是填充，不是信息。
- 读出声；一口气读不完的句子，先断。

## 代码与公式段落

- 公式前先给“人话版”：这个公式在算什么；公式后给“读法”：先看哪一项。
- 变量名误导时，换符号，保留原名注释。例：代码里叫 `x_max`，实际算的是 `mean(|x|)`；正文用 $a_k$，注一句“代码里叫 x_max”。
- 两个 scale、两个阶段，先命名再解释；不要用同一个词指两件事。
- 数值表前给“读法”：先看哪一列；表后给“一句话故事”：哪个值变了，为什么。
- 不要用比喻替代数字；比喻只负责“为什么”。

## 一个 before / after

**Before：**

> 令 $D=\operatorname{diag}(d_1,\ldots,d_K)$，将权重的第 $k$ 列乘 $d_k$，同时把输入的第 $k$ 个特征除以它。在不量化的精确算术模型中，$X'=XD^{-1}$，$W'=WD$，$X'W'^\top=XW^\top$。

**After：**

> 一句话：把重要通道的权重放大，再把输入除回去；数学上不变，但量化器看到的权重变了。
>
> 你可以把它想成记账：一边乘 4，另一边除 4，总账不变。只不过这次“乘 4”的是权重，“除 4”的是输入。
>
> 写成矩阵就是 $X'=XD^{-1}$、$W'=WD$；不量化时 $X'W'^\top=XW^\top$。

先给答案，再给比喻，最后给公式。读者不会在第一个符号上掉头。

## 常见翻车

- **段子化**：笑话把信息挤掉了。口语化是降低阅读阻力，不是增加娱乐节目。
- **比喻太远**：读者记住的是风扇，不是齿轮。比喻必须和概念共享结构。
- **没有边界**：读者用比喻推出错误结论，比如以为量化码是连续的。
- **一段三个比喻**：读者不知道抓哪个。一个主比喻，最多两个辅助。
- **为了顺口删 caveat**：技术信任崩了。caveat 可以搬家，不能消失。
- **变量名和解释打架**：`x_max` 实际是 mean，读者会以为你写错。换符号，保留原名注释。
- **把 API 文档改成故事**：读者只想查参数，不想看冒险。体裁不对，别硬套。
- **把口语化等同于变短**：如果原文缺的是“怎么落地”，补流程、例子和边界后可能更长；长度增加是信息，不是注水。
