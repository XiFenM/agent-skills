# 跨体裁语言契约

这是所有输出解释性文本的 Skill 共用的语言层。它管“怎么写”，不管“写什么、写到哪、能不能写”：

- 教学深度、节点、提问、状态与授权归 `guide-learning`。
- 页面结构、布局、交互与文件归 `lesson-pages`。
- 卡片拆分、等级、身份与 Markji 格式归 `memo-cards`。
- 文章与视频的完整方法归 `vivid-tech-writing` 的其余 references。

没有启用本 Skill 时，各 Skill 仍保留 2–4 条本地底线；启用时以本契约为准。冲突时先保事实、边界和授权，再保语言。

## 十条通用契约

1. **先给读者可抓的东西。** 解释性文本默认先交代场景、对象和问题，再展开机制与因果，最后给结论。技术文章可以用反常识结果、代价或问题开场，但不要用抽象定义开场。
2. **完整优先于短。** 短句是节奏工具，不是删信息的许可证。先保证主语、条件、因果完整，再把长句拆成短句；一句话如果让读者不知道“谁在什么条件下做什么”，它就不合格。
3. **一个主例贯穿。** 选一个能承载核心关系的例子，各节只补它的一部分；对照时只改局部，说明改动、结果和原因。不要每段换一个互不相关的小例子。
4. **术语和符号先定义。** 新术语先给经验或例子，再命名；符号先给含义、维度、单位和适用域。同一个词不要指两件事。
5. **具体锚点。** 用数字、单位、条件、真实规模和可复核的来源，代替“很多、很快、很复杂”。比喻负责“为什么”，数字负责“是多少”。
6. **事实、推断、未验证分开。** 不虚构经历、运行结果、引文或来源；没有核验的写成边界或 `[待核实]`。为了顺口删掉 caveat，是语言问题，也是可信度问题。
7. **语气朴实、直接、不俯视。** 用“你/我们”可以，但不要每句都加；不用“小白也能懂”“连我妈都会”。口语化是降低阅读阻力，不是加段子。
8. **一段一个中心关系。** 控制信息（目标、路径、权限、版本）一两行；不要用开头的目标清单代替讲解，也不要在每段附重复的免责说明。
9. **结论要能自评。** 读完结论，读者应能判断自己答对没有；答案或讲解要给出理由、条件和边界，不能只给一个结论词。
10. **读出声。** 一口气读不完的句子先拆；拆完还不能理解，说明缺的是背景、主语或因果，不是句子长度。

## 难懂机制的四件套

遇到“这段我看不懂”的机制，按顺序试：

1. **一句话答案**：先说“到底在干什么”，再上步骤、公式或代码。
2. **流程/阶段图**：用箭头把“输入 → 变换 → 输出 → 部署”画出来。
3. **日常物件主线比喻**：选读者每天用的东西，映射结构；2–3 个辅助比喻，每个标“哪里不像”。
4. **并排表**：两个容易混的 scale、阶段或角色，用一张表横向对比。

细做法见 [plain-language.md](plain-language.md)。比喻不能替代数字和 caveat。

## 按体裁

### 技术文章 / 博客

- 开头给场景、反常识结果、代价或问题；不要从定义开始。
- 全文选 2–3 个动作，不要九个全上；比喻 2–3 个主比喻，最多 4–5 个短比喻。
- 结尾回扣开头或升维，不要停在“综上所述”。
- 细节见 [moves.md](moves.md) 与 [plain-language.md](plain-language.md)。

### 教学讲解（guide-learning）

- 按深度阶梯组织：机制 → 设计理由 → 真实系统 → 边界 → 表达与迁移。
- 课程页默认先交代场景、对象和问题，再展开机制、理由和例子，最后归纳；一次答疑可以先直接回答，再补理由。
- 一个主例贯穿；分支只改局部，保留判断所需的调用双方、作用域与生命周期。
- 不为了“简短”省略全流程骨架；不为了结构硬造“旧方案失败、新方案胜出”的故事。
- 不写“不能提前释放”这种只有结论的禁令，写清主体、条件、动作和后果：主线程持有缓冲区、后台任务还要读取时，不能释放；先确认最后一次读取结束，再回收。
- 检查题考解释、预测、判断，不考复述和计算；不提前给开放题的答案。
- 开场不要逐项宣读目标、证据类型、记录路径和权限；这些控制信息一两行即可。
- 平台操作细节留在 `guide-learning`，不在本契约重复。

### 课程网页（lesson-pages）

- 页面承载讲解，对话只留指路、题目和反馈；页面不是状态或证据。
- 段落以读得顺为准，约 220 字是提醒拆段的参考；信息多时沿问题、机制、因果分段，或用图组织关系。
- 必要背景、主体、条件和解释照样写全；不靠省略词语、缩小字号或折叠关键步骤来减篇幅。
- 限制语句写清主体、条件、动作和原因；不把假设分支写成学习者犯过的错误。
- 不写为了配平版面的空泛句子；不在页面上写“示例”“示意图”“仅供参考”这类制作说明。
- 细节就近对应主例的代码行、数据或时序；分支先说明沿用位置，再展示少量修改和结果。
- HTML、布局、交互与文件约束留在 `lesson-pages`。

### 学习文章（guide-learning 的文章产物）

- 按主题、问题和论点组织，不按对话轮次排列；把纠错融入正确模型，不复刻纠错发生顺序。
- 事实、观察、推断和遗留问题分开；只写有材料支持且对目标读者有价值的 section。
- 语气只从四种里选，语气不改变事实标准：
  - `neutral-explanatory`：中性解释，少用“我”，判断以证据为主。
  - `peer-explanatory`：同行对谈，可以有判断和取舍，但不居高临下。
  - `technical-reference`：技术参考，先定义、后关系、再边界，少叙事。
  - `reflective-first-person`：第一人称复盘，只写真实经历，不虚构转折。
- 领域透镜是选材提示，不是固定 section；数字例子要有条件、单位和可复核来源；反例用来澄清边界，不为戏剧性虚构失败。
- 授权、section 配置、文件名与写入规则留在 `guide-learning` 的 `article-artifacts.md`。

### 记忆卡片（memo-cards）

- 一张卡只考一个回忆目标；背景、符号定义、解释步骤和例子是同一目标的支撑，不算新考点。
- 只看正面，就要知道讨论什么对象、哪个阶段、已知什么条件、要回答什么；正面不写出正在考查的结论、错因或判断方向。
- 答案先直接回答，再用完整句说明理由、步骤或比较关系，最后交代条件和边界；“结论”就是自评标准。
- 完整优先于短：不把 A 卡压成提示词；也不为统一长度把每张卡扩成教程。
- 不要求无序回忆超过 3 项的清单；需要列举时给结构线索、拆卡或改口述卡。
- 综合口述卡写明听众和场景，参考回答 60–90 秒，中文一般不超过约 400 字。
- 纠错卡保留真实错误原话，只纠错误的部分；不把合法但不够地道的表达伪装成红叉。
- 拆分、等级、身份、Markji 格式与检查清单留在 `memo-cards`。

### 视频口播

- 开场 15 秒 = 画面 + 反常识 + 承诺；不要从“大家好，今天我们来聊聊”开始。
- 口播三句一节：事实 → 为什么 → 所以你会看到什么。
- 每 30–45 秒一个变化；画面给“看见”，口播给“为什么”，不要互相复述。
- 完整方法见 [video-script.md](video-script.md)。

## 体裁对照

| 体裁 | 开头 | 结论位置 | 例子 | 主要禁忌 |
| --- | --- | --- | --- | --- |
| 技术文章 | 场景/反常识/代价 | 结尾回扣或升维 | 2–3 个动作，主例贯穿 | 定义开场、九个动作全上 |
| 教学讲解 | 场景/对象/问题 | 节点末尾归纳 | 一个主例，局部对照 | 目标清单开场、省略因果、提前泄题 |
| 课程网页 | 场景/对象/问题 + 骨架 | 节点末尾 | 主例贴近代码/数据/时序 | 空泛配平句、缩字号塞内容、制作说明 |
| 学习文章 | 问题/能力/用途 | 按 section 收束 | 主题综合，非对话记录 | 按轮次排列、事实与推断混写 |
| 记忆卡片 | 正面重建场景/条件/任务 | 答案开头给结论 | 一个目标，必要背景 | 正面泄题、压成提示词、清单超 3 项 |
| 视频口播 | 15 秒画面+反常识+承诺 | 回扣/可截图的话 | 每 30 秒一个变化 | 读文章、画面口播互相复述 |

## 共享检查清单

- [ ] 开头有场景、对象或问题，而不是抽象定义吗？
- [ ] 主语、条件、因果完整吗？有没有为了短删掉必要信息？
- [ ] 术语和符号先定义了吗？一个词只指一件事吗？
- [ ] 有一个主例贯穿吗？对照只改局部吗？
- [ ] 有具体数字、单位或可复核的来源吗？
- [ ] 结论能自评吗？边界、例外或失效条件写了吗？
- [ ] 事实、推断、未验证分开吗？有没有虚构经历或结果？
- [ ] 语气朴实、不俯视、不段子化吗？
- [ ] 体裁禁忌守住了吗（卡片不泄题、页面不提前写、教学不 spoiler）？
- [ ] 读出声，有没有喘不过气或听不懂的地方？

## 交接

- 本契约只改语言和表达顺序，不改事实、教学目标、卡片身份、页面结构、状态或授权。
- 需要更细的体裁规则时，回到对应 Skill 的 reference；不要把本契约扩成所有 Skill 的合集。
- 两个 Skill 同时启用时，语言冲突以本契约为准；结构、状态、授权冲突以领域 Skill 为准。
